## 顶层设计哲学（开发时必须遵守）

> **娱乐是入口，沉淀是目标。**

人的本能是娱乐，知识文化是精神的沉淀。V3.0 所有功能开发必须遵守：

1. **入口必须是娱乐**：孩子打开软件的第一感受必须是"好玩"，不是"要学习了"。禁止出现"开始学习""今天学什么"类触发抵触的按钮和话术。
2. **过程必须有即时快乐**：每一步操作都有正反馈、有乐趣、有成就感。禁止长时间无反馈的"埋头做题"。
3. **内核必须是知识**：玩的过程中，不知不觉学会数学概念和思维方式。禁止纯娱乐无知识的功能（那是游戏，不是教育）。
4. **沉淀需要时间**：不追求一次学会，每次玩一点点，日积月累。禁止"今天必须学完X章"的强制任务。
5. **最终目标是精神成长**：不是为了考试分数，而是为了建立自信心、思维方式、对世界的理解力。所有设计最终服务于这个目标。

**红线**：绝不为了娱乐而娱乐，也绝不为了知识而牺牲娱乐入口。两者必须同时满足。

## 3. 模块 A：宠物/伙伴系统

### 3.1 功能描述

孩子拥有一只随学习成长的虚拟宠物。学习行为转化为 XP 喂养宠物，宠物升级解锁外观/皮肤/互动语音。宠物有心情值，长时间不学习会低落（软提醒）。

### 3.2 数据模型

```json
{
  "pet": {
    "species": "cat",
    "name": "小橘",
    "level": 1,
    "exp": 0,
    "exp_to_next": 100,
    "mood": "happy",
    "mood_last_update": "2026-09-08T20:00:00",
    "unlocked_skins": ["default"],
    "current_skin": "default",
    "total_study_minutes": 0,
    "total_xp_earned": 0,
    "last_feed_time": null
  }
}
```

**字段说明**：
| 字段 | 类型 | 说明 |
|------|------|------|
| species | string | 物种：cat/rabbit/dino，初始为蛋(egg)，首次学习后孵化可选择 |
| name | string | 宠物名字，孩子可自定义 |
| level | int | 等级，初始1 |
| exp | int | 当前经验值 |
| exp_to_next | int | 升级所需经验，公式：100 * level^1.2 |
| mood | string | 心情：happy/normal/sad，根据上次学习时间计算 |
| mood_last_update | string | ISO时间，心情最后更新时间 |
| unlocked_skins | array | 已解锁皮肤ID列表 |
| current_skin | string | 当前使用的皮肤ID |
| total_study_minutes | int | 累计学习分钟数 |
| total_xp_earned | int | 累计获得XP |

**XP 获取规则**：
- 完成一次会话（≥3轮对话）：+20 XP
- 答对一道题（经评估块确认）：+5 XP
- 连续学习（combo）5连击：额外 +10 XP
- 掌握一个新知识点（掌握度≥0.7）：+30 XP
- 完成PBL项目一关：+50 XP

**心情计算规则**（每次读取宠物状态时实时计算）：
- 距上次学习 < 24小时：happy
- 24-72小时：normal
- > 72小时：sad
- 心情只影响展示和话术，不扣XP、不惩罚

### 3.3 API 设计

#### 3.3.1 获取宠物状态

```
GET /api/pet/{student_id}
```

**响应**：
```json
{
  "pet": { /* 完整pet对象 */ },
  "level_up_available": false,
  "mood_message": "小橘今天很开心，在等你一起学数学呢！"
}
```

#### 3.3.2 喂养宠物（学习后自动调用，也可手动）

```
POST /api/pet/{student_id}/feed
```

**请求**：
```json
{
  "xp_amount": 20,
  "source": "session_complete",
  "message": "完成一次学习会话"
}
```

**响应**：
```json
{
  "success": true,
  "xp_gained": 20,
  "new_exp": 120,
  "leveled_up": false,
  "new_level": null,
  "unlocked_skin": null,
  "pet": { /* 更新后pet对象 */ }
}
```

**升级逻辑**：当 exp >= exp_to_next 时，level+1，exp -= exp_to_next，重新计算 exp_to_next。每达到特定等级（5/10/15/20）解锁新皮肤。

#### 3.3.3 更换皮肤

```
POST /api/pet/{student_id}/skin
```

**请求**：`{ "skin_id": "sakura" }`

**响应**：`{ "success": true, "current_skin": "sakura" }`

#### 3.3.4 重命名宠物

```
POST /api/pet/{student_id}/rename
```

**请求**：`{ "name": "小橘" }`（长度≤10字符）

**响应**：`{ "success": true, "name": "小橘" }`

#### 3.3.5 宠物互动（点击宠物触发随机语音）

```
GET /api/pet/{student_id}/interact
```

**响应**：
```json
{
  "message": "喵～今天也要加油学数学哦！",
  "animation": "happy_jump"
}
```

### 3.7 验收标准

- [ ] 新学生首次学习后，可选择宠物物种并命名

- [ ] 宠物心情根据距上次学习时间正确变化（happy/normal/sad）
- [ ] 达到5/10/15/20级时解锁对应皮肤，可切换
- [ ] 点击宠物触发随机互动语音
- [ ] 升级时弹出庆祝动画
- [ ] 宠物状态在页面刷新后保持（持久化到学生档案）
- [ ] 旧学生档案（无pet字段）打开时自动初始化为默认宠物

## 4. 模块 B：卡片收集系统

### 4.1 功能描述

每掌握一个知识点，概率掉落一张对应"数学卡片"。卡片按知识图谱分类，有4种稀有度。可在收藏墙展示，重复卡片转化为"星光值"兑换皮肤。

### 4.2 数据模型

#### 4.2.1 学生档案中的卡片字段

```json
{
  "cards": {
    "collected": {
      "card_fraction_basic": {
        "count": 2,
        "first_obtained": "2026-09-08T20:00:00",
        "obtained_from": "mastery"
      }
    },
    "starlight": 50,
    "total_cards": 1,
    "unique_cards": 1
  }
}
```

#### 4.2.2 卡片定义库（前端/后端共享，存 `backend/knowledge/cards.py`）

```python
CARD_LIBRARY = {
    "card_fraction_basic": {
        "id": "card_fraction_basic",
        "name": "分数的基本性质",
        "category": "数与代数",
        "rarity": "common",  # common/rare/epic/legendary
        "knowledge_node": "fraction_basic",  # 关联知识图谱节点ID
        "front_icon": "🍰",
        "front_text": "一块蛋糕切8份吃4份，和切4份吃2份一样多",
        "back_text": "分子分母同乘同除（0除外），分数大小不变",
        "fun_fact": "古埃及人只用分子为1的分数，其他分数都要拆成几个单位分数之和"
    },
    # ... 每个知识点至少1张卡，共约80张
}
```

**稀有度与掉落概率**：
| 稀有度 | 概率 | 对应知识类型 | 星光值（重复） |
|--------|------|-------------|---------------|
| common（普通） | 60% | 基础概念 | 5 |
| rare（稀有） | 30% | 重要定理/公式 | 15 |
| epic（史诗） | 9% | 思维模型 | 40 |
| legendary（传说） | 1% | 跨章节综合/数学史 | 100 |

**掉落触发条件**：
- 掌握一个新知识点（掌握度从<0.7变为≥0.7）：必掉1张该知识点的卡
- 答对一道题：10%概率掉随机卡
- 完成PBL项目一关：必掉1张项目专属卡（稀有度≥rare）
- 连击10连击：50%概率掉1张随机卡

### 4.3 API 设计

#### 4.3.1 获取卡片库（全部卡片定义，用于展示收藏墙）

```
GET /api/cards/library
```

**响应**：`{ "cards": [ /* 全部卡片定义数组 */ ], "total": 80 }`

#### 4.3.2 获取学生已收集卡片

```
GET /api/cards/{student_id}
```

**响应**：
```json
{
  "collected": { /* collected对象 */ },
  "starlight": 50,
  "total_cards": 1,
  "unique_cards": 1,
  "completion_rate": 0.0125
}
```

#### 4.3.3 卡片掉落（学习事件触发，后端内部调用为主，也提供手动测试接口）

```
POST /api/cards/{student_id}/drop
```

**请求**：
```json
{
  "source": "mastery",
  "knowledge_node": "fraction_basic",
  "guaranteed": true
}
```

**响应**：
```json
{
  "success": true,
  "dropped": true,
  "card": { /* 卡片定义 */ },
  "is_new": true,
  "duplicate_count": 0,
  "starlight_gained": 0,
  "animation": "card_reveal_common"
}
```

**掉落逻辑**：
1. 如果 guaranteed=true 且指定了 knowledge_node，掉落该节点对应的卡
2. 否则按稀有度概率随机选择一张未充分收集的卡（优先掉未拥有的）
3. 如果是重复卡，转化为星光值，count+1
4. 如果是新卡，unique_cards+1

#### 4.3.4 星光值兑换皮肤

```
POST /api/cards/{student_id}/exchange
```

**请求**：`{ "skin_id": "sakura", "cost": 100 }`

**响应**：`{ "success": true, "starlight_remaining": 0, "unlocked_skin": "sakura" }`

## 5. 模块 C：连击/Combo 系统

### 5.1 功能描述

连续答对题目触发 Combo，3/5/10连击有不同的视觉特效、话术和XP加成。答错不惩罚，只是归零并鼓励。

### 5.2 数据模型

```json
{
  "combo": {
    "current": 0,
    "best_all_time": 0,
    "best_this_week": 0,
    "total_combos_5": 0,
    "total_combos_10": 0
  }
}
```

### 5.3 触发规则

| 事件 | combo变化 |
|------|----------|
| 答对一道题（评估块确认） | current + 1 |
| 答错一道题 | current = 0（不扣分，话术鼓励） |
| 会话结束 | current = 0，best_this_week 更新 |

**Combo 里程碑奖励**：
| Combo | 话术 | XP加成 | 特效 |
|-------|------|--------|------|
| 3 | "不错哦，继续保持！" | 无 | 小字提示 |
| 5 | "超棒！5连击了！" | +10 XP | 数字跳动+粒子 |
| 10 | "哇！10连击！你是数学小天才！" | +20 XP + 50%概率掉卡 | 全屏特效+音效 |

**注意**：Combo 只在"主动答题"场景触发（学生给出答案并被评估），对话中的小确认（"对""嗯"）不算，避免刷分。

### 5.4 API 设计

Combo 主要通过 SSE 实时推送，不需要独立API。但提供查询接口：

```
GET /api/combo/{student_id}
```

**响应**：`{ "current": 3, "best_all_time": 12, "best_this_week": 8 }`

### 5.5 SSE 事件

```json
{
  "type": "combo_update",
  "data": {
    "current": 5,
    "previous": 4,
    "milestone": "combo_5",
    "xp_bonus": 10,
    "message": "超棒！5连击了！"
  }
}
```

### 5.6 前端组件

| 组件名 | 位置 | 功能 |
|--------|------|------|
| `ComboIndicator` | 聊天页输入框上方 | 显示当前Combo数，里程碑时放大动画 |

### 8.3 模拟器技术设计

**核心组件**：`MissileSimulator`（Canvas 2D）

**模拟器状态**：
```javascript
{
  angle: 45,           // 发射角度（0-90度）
  power: 80,           // 发射力度（0-100，映射为初速度0-50 m/s）
  windSpeed: 0,        // 风速（-20~20 m/s，正为顺风）

  targetX: 100,        // 靶子X坐标
  targetY: 0,          // 靶子Y坐标
```

**物理计算**（纯前端JS，不需要后端）：
```javascript
// 斜抛运动公式（考虑水平风阻力简化为恒定加速度）
function calculateTrajectory(angle, power, windSpeed, windDirection) {
    const v0 = power * 0.5;  // 初速度
    const rad = angle * Math.PI / 180;
    const vx = v0 * Math.cos(rad);
    const vy = v0 * Math.sin(rad);
    const g = 9.8;
    const ax = windSpeed * windDirection * 0.1;  // 风的水平加速度（简化）
    
    const points = [];
    let t = 0;
    const dt = 0.05;
    while (true) {
        const x = vx * t + 0.5 * ax * t * t;
        const y = vy * t - 0.5 * g * t * t;
        if (y < 0) break;
        points.push({ x, y });
        t += dt;
        if (t > 30) break;  // 安全上限
    }
    return points;
}
```

**命中检测**：导弹落点（y=0时的x）与靶子X坐标的距离≤靶子宽度（默认5米）即命中。

**渲染**：
- 背景：渐变天空+地面
- 发射台：左侧固定位置
- 靶子：右侧，可移动
- 导弹：飞行中的小圆点+尾迹
- 轨迹：飞行结束后绘制抛物线（虚线）
- 参数面板：滑块+数值显示
- 发射按钮

### 8.4 关卡通关条件

## 9. 模块 G：兴趣共创机制

### 9.1 功能描述

不是系统给孩子选项目，而是通过对话了解孩子的兴趣，和孩子一起设计一个属于他自己的PBL项目。共创五步法：兴趣唤醒→聚焦→数学转化→项目规划→逐步实现。

### 9.2 数据模型

```json
{

      "status": "in_progress",  # planning/in_progress/completed/abandoned
      "steps": [
        {
          "id": 1,

          "status": "done",  # pending/in_progress/done
          "completed_at": "2026-09-08T20:30:00"
        },
        {
          "id": 2,

          "description": "比较不同任务的时间和收益，找出性价比最高的",
```

### 9.3 共创五步法的对话流程设计

#### 第1步：兴趣唤醒（1-2轮对话）

**小圆话术库**（随机选一条）：
- "你最近对什么感兴趣呀？有没有什么想搞明白的问题？"
- "今天不想学课本上的东西？没关系，我们来玩点别的。你平时最喜欢做什么？"
- "小圆最近在想一个问题：数学到底能用来干嘛？你有没有遇到过什么事，觉得'要是会数学就好了'？"

**孩子可能的回答及应对**：
| 孩子回答 | 小圆应对 |
|---------|---------|
| "我喜欢游戏" | → 进入第2步聚焦 |
| "我也不知道" | "没关系，我们慢慢想。你可以想想：游戏、运动、音乐、美食、科学、动物……哪个你最想多了解？"（提供选项启发） |
| "没什么特别的" | "那你昨天/周末做了什么？有没有什么觉得有意思的事？"（从生活切入） |
| "我什么都不喜欢" | "那我们来研究一个终极问题：怎么用最少的时间完成作业，剩下的时间都用来玩？"（把"不喜欢"转化为项目） |

#### 第2步：兴趣聚焦（1-3轮对话）

**目标**：从模糊的"喜欢游戏"聚焦到具体的"我想知道怎么最快赚到100万金币"。

**小圆话术**：
- "游戏里你最喜欢哪部分？是打怪升级？建房子？还是赚钱买装备？"
- "你有没有在游戏里遇到过什么算不明白的事？比如不知道该买哪个装备更划算？"
- "如果让你用数学解决游戏里的一个问题，你最想解决什么？"

#### 第3步：数学转化（1-2轮对话）

**目标**：和孩子一起把兴趣问题转化为一个可解的数学问题。

**小圆话术**：
- "那我们来算一算，怎么在游戏里最快赚到100万金币？"
- "这个问题需要知道：每种任务赚多少钱？花多少时间？有没有更优的组合？"
- "你觉得，要解决这个问题，我们需要先知道什么？"（引导孩子自己拆解）

#### 第4步：项目规划（1轮对话+确认）

**目标**：把问题拆解成3-5个步骤，每步对应一个数学知识点。

**小圆话术**：
> "我们把这个项目分成几步：
> 第一步：先统计你现在每天能赚多少钱（数据收集+统计）
> 第二步：算算不同任务的收益比（比和比例）
> 第三步：找最优组合（方程+优化）
> 第四步：验证一下，按这个方案真的能更快赚到吗？（实验验证）
> 
> 你觉得这个计划怎么样？要不要调整？"

**孩子确认后**，保存项目到 custom_projects，状态为 in_progress，第一步为 in_progress。

#### 第5步：逐步实现（复用PBL框架）

- 每一步相当于一个"关卡"，完成后标记done，进入下一步
- 小圆在每一步提供所需的数学知识支持（按需讲解，不系统灌输）
- 完成一步就庆祝、记录，然后进入下一步
- 项目可以暂停、放弃（不批评），状态变为 abandoned

## 10. 模块 H：前10分钟体验重构

### 10.1 功能描述

重构开场流程，从"心情打卡→情绪关怀→开始学习按钮→选模式"改为"宠物打招呼→小圆搭讪聊兴趣→自然引出数学问题→学会立刻能用→成功体验→游戏化奖励"。核心是移除"开始学习"按钮，让学习从聊天中自然发生。

### 10.2 新旧流程对比

**旧流程（V2.1）**：
```
登录 → 心情打卡 → 情绪关怀（共情+闲聊）→ [开始学习]按钮 → 选模式 → 学数学
```

**新流程（V3.0）**：
```
登录 → 宠物打招呼（如已解锁）→ 小圆"搭讪"：聊孩子上次提到的兴趣
  → 从聊天中自然引出一个数学问题（"你知道怎么算你这个英雄的暴击率吗？"）
  → 孩子好奇 → 小圆用这个问题教一个数学概念（只教1个，10分钟内）
  → 学会后立刻让孩子用这个概念解决他自己的问题
  → 成功体验 → 即时奖励（XP+卡片+宠物成长+Combo）
  → 小圆顺势引导："这个方法还能用来解决XX，要不要试试？" → 自然进入正式学习
```

### 10.3 关键改动点

#### 10.3.1 移除"开始学习"按钮

- 删除前端的"开始学习"按钮和遮罩
- 输入框始终可用，孩子可以随时打字
- 小圆的开场话术从"今天想学什么？"改为兴趣搭讪

#### 10.3.2 开场兴趣搭讪话术

**根据孩子是否有兴趣档案分两种情况**：

**有兴趣档案（interests.top3非空）**：
> "嘿！上次你说你在玩XX，打到哪了？" / "上次你说喜欢XX，最近有什么新发现吗？"

**无兴趣档案（新用户）**：
> "嗨～我是小圆。先不急着学数学，我们来聊聊天。你平时最喜欢做什么呀？"
> （识别兴趣后存入 interests 字段）

**从兴趣引出数学问题的话术模板**：
- "你知道吗？你喜欢的XX里面藏着好多数学！比如……"
- "我有个问题想请教你：如果……，你觉得会怎么样？"
- "你有没有想过，XX背后的数学原理是什么？"

#### 10.3.3 第一个数学问题必须"和我有关"

**规则**：开场后的第一个数学问题，必须来自孩子的兴趣档案或刚聊到的话题。禁止使用课本风格的抽象题（"小明有5个苹果"）。

**实现**：
- `interest_extractor.py` 扩展：新增 `get_opening_problem(interest)` 函数，根据兴趣返回一个趣味化的开场问题
- `chat.py` 开场时调用，将问题注入小圆的回复
- `persona.py` 新增规则：开场后的第一个数学问题必须关联孩子兴趣

#### 10.3.4 前10分钟只学1个概念

**规则**：
- 开场后的前10分钟（或前15轮对话），只聚焦1个数学概念
- 不追求多，只求"我学会了"的成功体验
- 难度调到孩子不可能做错（小圆引导极细，每一步都确认）
- 10分钟后，如果孩子状态好，自然过渡到更多内容；状态不好就收尾

**实现**：
- `chat.py` 新增"首次学习模式"状态：检测到是新用户或当天首次学习时，进入轻量模式
- 轻量模式下，`strategy_engine.py` 只选择最简单的策略，题目难度降1级
- 10分钟或15轮对话后，自动切换回正常模式

#### 10.3.5 学会立刻能用

**规则**：孩子学会一个概念后，小圆必须主动提出一个"用刚学的知识解决你的问题"的应用场景。

**示例**：
- 学会百分比 → "来，用刚学的百分比，算算你游戏里抽卡的概率是多少？"
- 学会方程 → "你刚才说想攒钱买XX，我们来算算每天攒多少，几天能买到？"
- 学会比例 → "你喜欢画画对吧？来算算画里人物的头身比是多少？"

### 11.9 顿悟时刻设计（V3.0 终极目标，P0）

> 顿悟时刻是数学思考上瘾的核心引擎。本模块负责识别、放大和记录孩子的顿悟体验。

#### 11.9.1 顿悟信号识别

**识别方式**：通过对话内容和模式匹配识别顿悟信号。

**信号类型**：

| 信号类型 | 识别规则 | 示例 |
|---------|---------|------|
| 感叹词触发 | 孩子消息包含"啊！""哇！""原来如此！""我知道了！""懂了！"等 | "啊！我知道了！应该先通分！" |
| 主动说出关键步骤 | 孩子在没有小圆提示的情况下，主动说出解题的关键步骤或方法 | "等等，如果设x为未知数的话..." |
| 态度转变 | 从"我不会""我不知道"转变为"让我试试""我想到了" | 上一轮说"我不会"，下一轮说"等等，我试试这样" |
| 提出新思路 | 孩子主动提出新的解题思路或方法，而非重复小圆的话 | "换个角度想的话，是不是可以用画图？" |
| 延迟顿悟 | 孩子在非学习时间（如下一次开场）主动说"昨天那道题我想通了！" | "小圆！昨天那道思考题我想通了！" |

**实现**：
- `backend/services/` 新增 `insight_detector.py`：规则式顿悟信号检测
- 检测函数：`detect_insight(messages: List[Message]) -> Optional[InsightEvent]`
- 每次孩子发消息后调用，检测到顿悟事件后触发庆祝流程

#### 11.9.2 顿悟时刻放大庆祝

**检测到顿悟后，小圆必须执行的流程**：

1. **暂停当前流程**：不继续下一题，不继续讲解
2. **明确指出**："等等！你刚才说的那句话——你自己想通了！太厉害了！"
3. **放大快感**："刚才那一步就是关键！你是怎么想到的？"（让孩子复述思考过程，加深体验）
4. **触发特效**：通过SSE推送 `insight_event`，前端展示金色光芒+特殊音效+顿悟徽章动画
5. **大额奖励**：+100 XP（普通答对只有+5），概率掉落史诗/传说卡片
6. **记录日志**：写入教学日志，标记为"顿悟时刻"，包含孩子的原话和思考过程

**SSE事件格式**：
```json
{
  "type": "insight_event",
  "data": {
    "insight_type": "exclamation",
    "student_quote": "啊！我知道了！应该先通分！",
    "xp_reward": 100,
    "card_dropped": { /* 卡片对象或null */ },
    "badge_unlocked": { /* 徽章对象或null */ },
    "effect": "golden_burst"
  }
}
```

#### 11.9.3 引导给线索不给答案

**persona.py 新增规则**：
- 孩子卡壳时，禁止直接说"用XX方法""应该这样做""答案是XX"
- 必须给线索或视角："如果我们把不知道的数用字母代替，会怎么样？""你看看题目里哪两个量是有关系的？""试试画个图？"
- 评估块新增检测：如果小圆的回复包含直接答案或直接方法，标记为 `direct_answer=true`，触发警告（开发期），后续可自动改写

**chat.py 引导策略**：
- 卡壳1次：给一个小提示
- 卡壳2次：换一个角度提示
- 卡壳3次：降级为更简单的子问题，拆成更小的步骤
- 永远不直接给答案，除非孩子明确说"我不想想了，直接告诉我"（此时也要先问"确定吗？再想想说不定就通了"）

#### 11.9.4 主动挑战机制

**挑战题库**：
- `backend/knowledge/` 新增 `challenge_problems.py`：挑战题库，按知识点和难度分级
- 每道挑战题有：题目、难度（1-5星）、预计思考时间、提示线索（3级）、解题思路
- 挑战题特点：有趣、有挑战性、和生活/兴趣相关、不是常规练习题

**挑战邀请话术**：
- "这道题有点难，目前只有10%的人做出来，你敢挑战吗？"
- "今天有一道思考题，想不想试试？不想也没关系。"
- "你最近状态超好，给你一道有点难度的，要不要试试？"

**挑战成功奖励**：
- 比普通答题高3-5倍XP
- 必掉稀有以上卡片
- 挑战徽章（"挑战者""难题杀手"等）
- 教学日志特别记录

#### 11.9.5 每日思考题

**机制**：
- 每次会话结束时，小圆留一道"想不想都可以"的思考题
- 思考题特点：有趣、开放性、不需要立刻做、可以在生活中突然想通
- 不强制，不检查，孩子想通了主动分享会有巨大成就感和奖励

**示例思考题**：
- "为什么井盖是圆的不是方的？"（几何）
- "如果你有一个无限大的池塘，第一天放1片荷叶，每天翻倍，30天填满。第几天填了一半？"（指数/逆向思维）
- "为什么45度角扔东西飞得最远？"（三角函数/物理）
- "一个人跑100米用10秒，另一个人跑50米用5秒，他们一样快吗？"（速度/比例）

**第二天开场**：
- 小圆主动问："昨天那道思考题，你有没有突然想通？"
- 如果孩子想通了：巨大庆祝 + 顿悟奖励 + "你自己在生活中想通的，这才是真正的学会了！"
- 如果没想通："没关系，好问题值得慢慢想。说不定哪天走路的时候突然就通了。"

```python
_clients: dict[str, AsyncOpenAI] = {}

def get_client() -> AsyncOpenAI:
    provider = get_current_provider()
```

### J.5 Function Calling 降级与 SymPy 后端校验

**不支持 tools 的提供商**，采用两级策略：

1. **提示词引导**：在 system prompt 中加入计算规则，要求 LLM 写出计算过程
2. **SymPy 后端校验**：LLM 输出完成后，后端提取计算表达式，用 SymPy 验证结果。发现错误时，通过 SSE 推送修正提示，让小圆重新输出正确结果

**SymPy 校验实现**（`backend/services/calc_verifier.py` 已有基础，扩展）：
- 从 LLM 输出中正则提取数学表达式（如 `2+3*4`、`x = 15/3`）
- 用 SymPy 计算正确结果
- 对比 LLM 给出的结果，不一致则标记错误
- 错误时生成修正提示："刚才的计算有误，正确结果是 X，我们重新算一下"
