## 1. 总体评价

### 1.2 核心矛盾

作为**数学**助教，项目最大的短板是：**LLM 负责了所有数学计算，但没有任何精确计算验证机制**。LLM 会算错，而系统完全信任它的结果和评估。

## 2. 教育心理学框架整合

> 本章独立于代码 bug，是教学理念层面的系统性补充。项目核心理念本身扎根于教育心理学，但"有理念缺框架"，补上认知负荷和元认知两块后，教学效果会有质的提升。

### 2.1 当前已隐含的教育心理学原理

| 理论 | 提出者 | 项目中的体现 | 做得如何 |
|------|--------|-------------|---------|
| **成长型思维** | Dweck | "旧积木松了，不是笨"、归因重构话术 | ✅ 做得好，persona.py 红线明确 |
| **间隔重复** | Ebbinghaus | repetition.py 间隔复习调度 | ✅ 有实现，但题目覆盖不全 |
| **最近发展区/脚手架** | Vygotsky | 状态机引导、分步提问、不直接给答案 | ⚠️ 有框架，但脚手架的"渐隐"机制缺失 |
| **正向强化** | Skinner | 徽章系统、庆祝动效、信心曲线 | ⚠️ 有激励，但奖励绑定不够精准 |
| **自我决定理论** | Deci & Ryan | 双模式自主选择、保底日不批评 | ✅ 核心理念到位 |
| **归因训练** | Weiner | 卡壳时归因重构为"旧积木松了" | ⚠️ 有话术，但没有系统的归因追踪 |

### 2.2 缺失的重要理论（按优先级排序）

#### 🔴 EP-P0-1：认知负荷理论（Sweller）— 最该补

**核心观点**：人的工作记忆容量有限（约4±1个信息块），教学必须控制认知负荷。负荷分为三类：内在负荷（知识点本身难度）、外在负荷（呈现方式）、关联负荷（建构理解）。

**当前问题**：
- `persona.py:35` 说"单条回复不超过5句话"，但没有区分三类负荷
- LLM 可能在一条回复里同时讲概念+公式+例题+步骤，超载
- 没有根据学生的**先前知识水平**动态调整信息密度
- 高难度知识点（difficulty≥4）没有强制拆分

**落地建议**：

1. **在 persona.py 中增加认知负荷控制规则**（加入 system prompt）：
```
## 认知负荷管理（必须遵守）
- 每轮只传递1个核心信息块，新概念先用生活化比喻锚定
- 高难度知识点（难度≥4）必须拆成至少2轮：第一轮只建立直觉，第二轮再讲形式化
- 学生连续2轮表示困惑→自动降级：更简单的比喻、更小的步骤、等待学生确认
- 例题和推导分轮次呈现，绝不一轮塞完
- 外在负荷最小化：用清晰的结构、避免冗余表述、公式用LaTeX渲染
```

2. **后端动态注入约束**：在 `chat.py` 的 `process_message` 中，根据当前知识点难度 + 学生掌握度，动态追加"本轮只讲X"的指令：
```python
if sess.topic_id:
    node = syllabus.get_node(sess.topic_id)
    if node and node.difficulty >= 4 and student.mastery.get(sess.topic_id, 0) < 0.5:
        extras.append("[系统提示：当前知识点难度较高且学生掌握度低，本轮只讲一个最基础的直觉，不要展开推导和例题]")
```

3. **困惑检测与自动降级**：在 `chat.py` 中检测学生连续困惑（"不懂""不会""还是不明白"出现2轮以上），自动注入降级指令。

**验收标准**：
- [ ] system prompt 包含认知负荷管理规则
- [ ] 高难度知识点强制拆分多轮
- [ ] 连续困惑时自动降级信息密度
- [ ] 每轮回复不超过1个核心信息块

#### 🔴 EP-P0-2：元认知策略训练 — 核心能力，只有雏形

**核心观点**：教学生"学会学习"比教知识更重要。元认知包括三个环节：**计划**（预判怎么做）、**监控**（意识到卡在哪）、**评估**（判断自己是否真懂）。

**当前问题**：
- `chat.py:82-84` 有"盲区自报"（让学生自己说哪里不踏实），这是元认知的**监控**环节
- 但没有**计划**训练（让学生先预判"这题我会怎么做"）
- 没有**评估**训练（做完后让学生自己判断"我真的懂了吗"）
- 没有元认知策略的**显性教学**（教学生"遇到不会的题第一步该做什么"）
- 学生画像中没有元认知能力的追踪

**落地建议**：

1. **状态机增加元认知环节**：
   - 在 `CORE_DERIVE` 之前增加 `PLAN` 状态：让学生先说说"你觉得这题该怎么入手"，再开始推导
   - 在 `WRAP_UP` 收尾时，固定问一个元认知评估问题："今天学的这个方法，你觉得什么时候还能用？"
   - 状态机更新为：`BLIND_SPOT → PLAN → CORE_DERIVE → EXAMPLE_CHECK → ERROR_REVIEW → OPTIONAL_VARIANT → WRAP_UP(含元认知评估) → DONE`

2. **建立元认知策略库**（新增 `backend/agent/metacognition.py`）：
```python
STRATEGIES = {
    "read_unknown": {
        "name": "画图理解",
        "trigger": ["读不懂", "看不明白", "题目在说什么"],
        "prompt": "题目读不懂的时候，我们试试把题目里的条件画成图好不好？把已知的量标上去，看看能不能看出关系～",
    },
    "calculation_error": {
        "name": "分步验算",
        "trigger": ["算错了", "结果不对", "怎么算出来不一样"],
        "prompt": "算错了没关系，我们试试分步验算：把每一步单独写出来，盖住答案重算一遍，看看哪一步出了问题～",
    },
    "no_idea": {
        "name": "从问题倒推",
        "trigger": ["没思路", "不知道从哪开始", "怎么下手"],
        "prompt": "没思路的时候，我们试试从问题倒推：题目要我们求什么？要求出这个，需要先知道什么？一步步往回找～",
    },
    "concept_confusion": {
        "name": "回到定义",
        "trigger": ["概念搞混了", "分不清", "这两个有什么区别"],
        "prompt": "概念搞混了，我们回到最原始的定义：用自己的话说说，这两个概念分别是什么意思？举个例子就清楚了～",
    },
}
```

3. **在评估块中增加元认知字段**：
```json
{
  "metacognition_observed": "plan/monitor/evaluate/none",
  "strategy_suggested": "策略名或空",
  "independent_success": true
}
```

4. **学生画像增加元认知追踪**（`student.py` 的 `StudentProfile`）：
```python
metacognition_level: float = 0.0  # 元认知能力评分
strategy_use: dict[str, int] = {}  # 各策略使用次数
independent_success_rate: float = 0.0  # 独立做对比例
```

**验收标准**：
- [ ] 状态机包含 PLAN（计划）和 WRAP_UP 评估环节
- [ ] 元认知策略库覆盖至少4种常见卡点场景
- [ ] 评估块包含元认知观察字段
- [ ] 学生画像追踪元认知能力发展
- [ ] 学生主动说出卡点的频率随时间提升

#### 🟡 EP-P1-1：刻意练习（Ericsson）— 反馈闭环不完整

**核心观点**：有效练习 = 明确目标 + 即时反馈 + 针对性纠正 + 走出舒适区。不是"做了很多题"，而是"每道题都有针对性的进步"。

**当前问题**：
- 有错题溯源（两问协议），但**没有针对性的重复练习**
- 学生答错后，LLM 讲解一遍就过了，没有"换一道同类型题再做"的闭环
- 没有区分"粗心错误"和"概念错误"的不同练习策略
- 没有"走出舒适区"的渐进难度设计

**落地建议**：

1. **概念错误 vs 粗心错误的差异化处理**：
   - 概念错误 → 讲解后**立即出一道同类型基础题**验证，独立做对才标记掌握
   - 粗心错误 → 教检查策略（盖住答案重算、代入验证），明确说"这个不用多刷题"
   - 在 `assessment.py` 的 `apply_eval` 中，根据 `error_type` 字段触发不同后续流程

2. **掌握确认机制**：
   - 讲解后必须有验证环节，不能"讲完就过"
   - 核心知识点（`is_core=True`）必须独立做对一道题才能达到掌握度0.7以上
   - 在 `chat.py` 中，`EXAMPLE_CHECK` 状态后增加验证逻辑：学生答对 → 掌握度可提升；答错 → 回到 `CORE_DERIVE` 重新讲解

3. **渐进难度设计**：
   - 掌握度0.6 → 同构变式（换数字）
   - 掌握度0.75 → 近迁移（换情境）
   - 掌握度0.9 → 远迁移（跨知识点综合）
   - 在 `repetition.py` 或新增 `practice.py` 中实现难度梯度

**验收标准**：
- [ ] 概念错误后有同类型题验证环节
- [ ] 粗心错误教检查策略，不增加题量
- [ ] 核心知识点需独立做对才能标记掌握
- [ ] 掌握度与题目难度梯度对应

#### 🟡 EP-P1-2：自我效能感（Bandura）— 信心曲线计算方式错误

**核心观点**：自我效能感（"我能做到"的信念）来自四个来源，按强度排序：**成功体验**（最强）> 替代经验 > 言语说服 > 生理状态。

**当前问题**：
- `assessment.py:54-62` 的信心 = 平均掌握度 + 情绪加成，这是**错误的**
- 掌握度高 ≠ 自我效能感高（学生可能靠提示做对，但自己不觉得能独立完成）
- 没有追踪"独立做对"vs"靠提示做对"的区别
- 没有利用"替代经验"（"之前XX知识点你也觉得难，后来搞定了"）

**落地建议**：

1. **重构信心曲线计算**（修改 `assessment.py`）：
```python
def update_confidence(student, eval_data):
    # 自我效能感四来源加权
    # 1. 成功体验（权重最高）：独立做对的次数
    independent_success = eval_data.get("independent_success", False)
    success_delta = 0.12 if independent_success else 0.0
    
    # 2. 替代经验：主动调用"你之前也搞定过类似的"时加分
    # （由 LLM 在 prompt 中使用替代经验话术时标记）
    vicarious_delta = 0.03 if eval_data.get("vicarious_experience_used") else 0.0
    
    # 3. 言语说服：具体的表扬（非"你真聪明"）
    # （由 LLM 评估是否给出了具体的思维动作表扬）
    persuasion_delta = 0.02 if eval_data.get("specific_praise") else 0.0
    
    # 4. 生理/情绪状态
    emotion_delta = {
        "confident": 0.05, "neutral": 0.0, 
        "frustrated": -0.08, "tired": -0.03
    }.get(eval_data.get("emotion", "neutral"), 0.0)
    
    current = student.confidence_trend[-1]["score"] if student.confidence_trend else 0.5
    new_confidence = max(0.0, min(1.0, current + success_delta + vicarious_delta + persuasion_delta + emotion_delta))
    student.confidence_trend.append({"date": student.today_iso(), "score": round(new_confidence, 2)})
```

2. **替代经验主动调用**：在 `persona.py` 中增加规则——当学生遇到困难时，主动回顾她之前的成功经验：
```
## 自我效能感建设
- 学生说"我不会"时，先调用替代经验："你上次学XX也觉得难，后来不是搞定了吗？"
- 优先让学生体验"小成功"：把题拆到她能独立做对的程度
- 表扬具体的思维动作（"你先想到找卡壳的那一步"），不表扬"聪明"
- 独立做对是信心的最强来源，尽量创造独立完成的机会
```

3. **阶梯式小目标**：在 `chat.py` 中，将大任务拆成可独立完成的小步骤，每完成一步都给明确的正向反馈。

**验收标准**：
- [ ] 信心曲线基于四来源加权，不再是掌握度+情绪
- [ ] 独立做对的权重最高
- [ ] system prompt 包含替代经验调用规则
- [ ] 大任务拆分为小成功步骤

#### 🟡 EP-P1-3：情感过滤假说（Krashen）— 焦虑管理不够系统

**核心观点**：焦虑、动机、自信心构成"情感过滤器"，过滤器越强，知识越难进入大脑。低焦虑环境是有效学习的前提。

**当前问题**：
- 有情绪关怀（心情打卡、累了就停），但**没有焦虑的主动识别和干预**
- 学生说"好难"时，系统只是降低任务，但没有教**焦虑管理策略**
- 没有区分"良性焦虑"（适度紧张促进表现）和"恶性焦虑"（过度紧张抑制思考）

**落地建议**：

1. **焦虑水平评估**：在评估块中增加 `anxiety_level: low/medium/high`，LLM 根据学生语言判断（"好难""不会""烦死了""我不行"→高焦虑）

2. **高焦虑干预流程**（在 `chat.py` 中检测到高焦虑时触发）：
```python
if eval_data.get("anxiety_level") == "high":
    extras.append(
        "[系统提示：学生当前焦虑水平较高。请先做情绪调节再继续学习："
        "①共情接纳（'这题确实有点难，觉得难很正常'）；"
        "②教一个简单的焦虑管理技巧（如'我们先深呼吸三次'）；"
        "③把任务拆到最小步（'我们先只看题目在问什么，不急着做'）；"
        "④绝不加码、绝不说'这么简单都不会']"
    )
```

3. **积极自我对话训练**：在 `persona.py` 中增加规则，教学生把消极对话替换为积极对话：
```
## 焦虑管理
- 学生说"我不会"→引导改为"我现在还不会，但可以学"
- 学生说"我好笨"→立即归因重构："不是笨，是这个积木还没搭稳，我们搭稳就好"
- 高焦虑时先深呼吸、分解任务、正向暗示，再开始学习
- 区分良性焦虑（"我有点紧张但我想试试"）和恶性焦虑（"我不行我做不到"），前者鼓励，后者先调节
```

4. **焦虑模式追踪**：在学生画像中记录什么类型的题、什么时间段容易焦虑，提前干预。

**验收标准**：
- [ ] 评估块包含焦虑水平评估
- [ ] 高焦虑时有明确的情绪调节流程
- [ ] 教学生积极自我对话替换策略
- [ ] 学生画像追踪焦虑模式

#### 🟢 EP-P2-1：掌握学习理论（Bloom）— 没有"未掌握不前进"机制

**核心观点**：只要给足够的时间和适当的帮助，95%的学生都能掌握任何知识点。关键是"掌握前不前进"。

**当前问题**：
- 有掌握度追踪，但学生可以跳过未掌握的知识点学新的
- 知识图谱有前置依赖，但没有强制检查
- 没有"纠正性反馈"循环（答错→诊断→针对性教学→再测试→确认掌握）

**落地建议**：
1. 学生选择新知识点时，检查前置依赖掌握度，低于0.5时**温柔提醒**"这个知识点需要先把XX搞稳"，但不强制阻止（保护自主性）
2. 核心知识点（`is_core=True`）必须达到0.7才能标记为"已掌握"
3. 建立"掌握确认"机制：讲解后必须独立做对一道题才算掌握

---

#### 🟢 EP-P2-2：迁移学习理论 — 变式题设计不够系统

**核心观点**：学习的最终目的是迁移（在新情境中应用）。迁移分为近迁移（类似情境）和远迁移（不同情境）。

**当前问题**：
- 有变式题环节（OPTIONAL_VARIANT），但是"选做"，且题目靠 LLM 自由生成
- 没有系统的近迁移→远迁移梯度设计
- 没有教学生"识别不同情境下的相同数学结构"

**落地建议**：
1. 变式题分为三级：同构变式（换数字）→近迁移（换情境）→远迁移（跨知识点综合）
2. 掌握度0.6→同构变式，0.75→近迁移，0.9→远迁移
3. 做完变式题后，引导学生反思"这两道题有什么相同的数学结构"

```python
EDU_PSYCHOLOGY_FRAMEWORK = """
## 教育心理学原则（内化执行）

### 认知负荷管理
- 每轮只传递1个核心信息块，新概念用生活化比喻锚定
- 高难度知识点（难度≥4）必须拆成至少2轮，第一轮只建立直觉
- 学生连续2轮困惑→自动降级：更简单的比喻、更小的步骤、更多等待
- 例题和推导分轮次呈现，绝不一轮塞完

- 解题前先问："你觉得第一步该做什么？"（计划）
- 卡壳时先问："你觉得卡在哪一步？"（监控）
- 收尾时问："这个方法你觉得什么时候还能用？"（评估/迁移）
- 教学生具体策略：读不懂→画图、算不对→分步验算、没思路→从问题倒推

### 刻意练习闭环
- 概念错误→讲解后立即出一道同类型基础题，独立做对才算掌握
- 粗心错误→教检查策略，不需要多练

### 自我效能感建设
- 优先让学生体验"小成功"：把题拆到她能独立做对的程度
- 遇到困难时调用替代经验："上次XX你也觉得难，后来不是搞定了吗？"
- 表扬具体的思维动作，不表扬"聪明"
- 独立做对是信心的最强来源，尽量创造独立完成的机会

### 焦虑管理
- 检测到高焦虑（"好难""不会""烦死了"）→先情绪调节再学习
```

## 3. 认知发展评估模型

> 本章独立于教育心理学理论，是"理论→工程实现"的桥梁。第2章回答"用什么教育心理学理论"，本章回答"怎么知道孩子处于什么发展水平、并据此动态调整教学"。前者是规则库，后者是自适应引擎。

### 3.1 为什么必须有评估模型

| 问题 | 说明 |
|------|------|
| **同龄差异大** | 六年级学生有的还在"具体运算阶段"（需要实物/画图才能理解），有的已进入"形式运算阶段"（能做抽象演绎推理），差异可达2-3年 |
| **领域不均衡** | 同一个孩子，代数可能已经抽象思维了，但几何可能还需要具体图形支撑 |
| **错配的代价** | 教学方法高于认知水平→挫败焦虑；低于认知水平→无聊厌学。两者都会触发"情感过滤"（Krashen） |
| **当前系统盲区** | 只有 `grade=6` 一个静态标签，`persona.py` 的教学策略固定，没有根据孩子的实际认知水平动态调整 |

**核心矛盾**：当前系统假设"所有六年级孩子认知水平相同"，但发展心理学告诉我们这是错的。

### 3.2 理论基础

#### 3.2.1 Piaget 认知发展阶段论（最核心）

| 阶段 | 年龄 | 核心特征 | 数学教学启示 |
|------|------|---------|-------------|
| 具体运算 | 7-11岁 | 能逻辑推理但需要具体事物支撑；理解守恒、分类、序列；**不能**做假设演绎 | 必须用画图、实物、生活例子；公式要从具体例子归纳，不能直接给抽象定义 |
| 形式运算 | 11岁+ | 能抽象思维、假设演绎、理解符号、处理"如果…那么…"；**但发展不均衡，有的人到成年才达到** | 可以直接讲抽象定义、做变式推理、理解"为什么"的形式化证明 |

> **关键洞察**：六年级（11-12岁）正处于**具体运算→形式运算的过渡期**，这是最需要评估的阶段。有的孩子已经过渡完成，有的还没有。

#### 3.2.2 工作记忆容量（信息加工理论）

- 成人工作记忆约 4±1 个信息块，儿童更少
- 工作记忆容量直接决定了"一次能讲多少步"
- 认知负荷理论（见第2章 EP-P0-1）必须与工作记忆容量匹配

#### 3.2.3 执行功能（Executive Function）

三个核心成分，随年龄发展：
- **抑制控制**：能否忍住不跳步、不粗心
- **认知灵活性**：能否换一种方法解题、从不同角度看问题
- **工作记忆**：能否在脑中同时 hold 住多个条件

#### 3.2.4 Vygotsky 最近发展区（已有，见第2章）

- 独立能做的 = 实际发展水平
- 靠提示能做的 = 潜在发展水平
- 两者之间 = 最近发展区（ZPD）
- **教学应该瞄准 ZPD**，但 ZPD 的大小因人而异

#### 3.2.5 Krathwohl 情感领域（与焦虑管理配合）

- 接受→反应→评价→组织→内化
- 数学焦虑高的孩子，在"接受"阶段就被阻断了

### 3.3 评估维度（7个维度）

```
认知发展画像 (CognitiveProfile)
├── 1. 认知阶段 (cognitive_stage)
│   ├── concrete: 具体运算（需要具体支撑）
│   ├── transitional: 过渡期（部分抽象）
│   └── formal: 形式运算（纯抽象推理）
│
├── 2. 工作记忆容量 (working_memory_capacity)
│   ├── low: 2-3块（一次只能讲1-2步）
│   ├── medium: 3-4块（一次能讲2-3步）
│   └── high: 4+块（一次能讲3步以上）
│
├── 3. 抽象思维能力 (abstract_thinking)
│   ├── 能否理解符号代表（a, x）
│   ├── 能否做假设演绎（如果…那么…）
│   └── 能否理解"为什么"的形式化证明
│
├── 4. 元认知能力 (metacognition_level)
│   ├── 能否主动说出"我卡在哪"
│   ├── 能否自我检查
│   └── 能否选择合适的解题策略
│
├── 5. 执行功能 (executive_function)
│   ├── 抑制控制：是否频繁跳步/粗心
│   └── 认知灵活性：能否换方法
│
├── 6. 数学焦虑 (math_anxiety)
│   ├── low / medium / high
│   └── 触发场景（考试/口算/应用题/几何）
│
└── 7. 学习偏好 (learning_preference)
    ├── visual: 视觉型（画图/图表）
    ├── verbal: 语言型（听讲解/讨论）
    └── kinesthetic: 动觉型（动手/实物操作）
```

#### 3.4.2 第二层：动态评估（对话过程中持续观察）

不需要专门做题，在日常对话中通过**行为指标**持续更新认知画像。在 `assessment.py` 的 `apply_eval` 中增加：

```python
def update_cognitive_profile(student: Student, eval_data: dict, conversation_features: dict) -> None:
    profile = student.cognitive_profile

    # 1. 认知阶段推断
    if conversation_features.get("requested_diagram"):
        # 学生主动要求画图 → 偏具体运算
        profile.abstract_thinking = max(0.1, profile.abstract_thinking - 0.03)
        profile.learning_preference = "visual"
    if conversation_features.get("asked_why"):
        # 学生主动问"为什么" → 形式运算萌芽
        profile.abstract_thinking = min(1.0, profile.abstract_thinking + 0.02)
        profile.metacognition_level = min(1.0, profile.metacognition_level + 0.02)

    # 2. 工作记忆推断
    if conversation_features.get("frequent_step_questions"):
        # 频繁问"这一步怎么来的" → 工作记忆容量较低
        if profile.working_memory_capacity != "low":
            profile.working_memory_capacity = "low"

    # 3. 执行功能推断
    if conversation_features.get("careless_errors_frequent"):
        profile.executive_function["inhibition"] = max(0.1, profile.executive_function["inhibition"] - 0.03)
    if conversation_features.get("tried_alternative_method"):
        profile.executive_function["flexibility"] = min(1.0, profile.executive_function["flexibility"] + 0.03)

    # 4. 数学焦虑推断
    if conversation_features.get("avoidance_behavior"):
        profile.math_anxiety = min(1.0, profile.math_anxiety + 0.04)
    if conversation_features.get("主动挑战难题"):
        profile.math_anxiety = max(0.0, profile.math_anxiety - 0.02)

    # 5. 元认知推断
    if conversation_features.get("self_corrected"):
        profile.metacognition_level = min(1.0, profile.metacognition_level + 0.03)
    if conversation_features.get("stated_blind_spot"):
        profile.metacognition_level = min(1.0, profile.metacognition_level + 0.02)
```

```python
def extract_conversation_features(user_message: str, eval_data: dict, history: list) -> dict:
    features = {}
    # 学生是否要求画图
    features["requested_diagram"] = any(k in user_message for k in ["画个图", "画图", "画一下", "图呢"])
```

### 3.5 认知画像如何驱动教学策略

在 `persona.py` 的 `build_system_prompt` 中，根据认知画像动态调整教学规则：

```python
def _cognitive_adaptation(profile: CognitiveProfile) -> str:
    rules = []

    # 1. 认知阶段适配
    if profile.cognitive_stage == "concrete":
        rules.append(
            "## 认知适配：学生处于具体运算阶段\n"
            "- 每个新概念必须先用画图/实物/生活例子引入，不能直接给抽象定义\n"
            "- 公式要从具体例子归纳出来，让学生自己'发现'规律\n"
            "- 避免使用'假设''设x为任意数'等纯抽象表述\n"
            "- 每讲完一步，问'这一步你能在图上指出来吗？'"
        )
    elif profile.cognitive_stage == "transitional":
        rules.append(
            "## 认知适配：学生处于过渡期\n"
            "- 可以先给具体例子，再引导到抽象公式\n"
            "- 适当使用'如果…那么…'的表述，但要配合具体例子\n"
            "- 鼓励学生尝试不画图直接推理，但卡住时随时可以回到画图"
        )
    else:  # formal
        rules.append(
            "## 认知适配：学生已进入形式运算阶段\n"
            "- 可以直接讲抽象定义和形式化证明\n"
            "- 多问'为什么可以这样''有没有其他方法'，培养深度推理\n"
            "- 可以引入更有挑战性的变式题和综合题"
        )

    # 2. 工作记忆容量适配
    if profile.working_memory_capacity == "low":
        rules.append(
            "- 学生工作记忆容量较小：每次只讲1步，等学生确认后再讲下一步\n"
            "- 重要的中间结果要写出来（或让学生写），不要要求在脑中记住\n"
            "- 避免在一句话里包含3个以上条件"
        )
    elif profile.working_memory_capacity == "high":
        rules.append(
            "- 学生工作记忆容量较大：可以一次讲2-3步，然后让学生复述\n"
            "- 可以适当增加信息密度"
        )

    # 3. 数学焦虑适配
    if profile.math_anxiety >= 0.6:
        rules.append(
            "- 学生数学焦虑较高：\n"
            "  - 绝对避免限时压力（不说'快一点''这题很简单'）\n"
            "  - 把题拆到最小步，确保每一步都能体验成功\n"
            "  - 多使用'我们一起试试看'而非'你来做'\n"
            "  - 焦虑触发时先做情绪调节再继续"
        )

    return "\n\n".join(rules)
```

## 4. 数学思维模型体系

> 本章是"教学内容体系"层面的建设。教育心理学（第2章）回答"怎么教"，认知评估（第3章）回答"教谁"，本章回答"教什么思维方法"。知识点会遗忘，但思维模型是可迁移的核心能力。

### 4.1 为什么需要显式教授思维模型

| 问题 | 说明 |
|------|------|
| **"听懂了不会做"** | 学生听懂了知识点但不会解题，往往不是知识点没掌握，而是不知道用什么思维方法去拆题 |
| **知识会遗忘，思维不会** | 毕业多年后公式可能忘了，但"从结果倒推""画图辅助""拆成小步"这些思维方法终身可用 |
| **当前系统盲区** | 系统教的是"知识点"（有理数、方程、几何），没有显式的思维方法教学。学生只能靠自己"悟"，悟性差的就卡住了 |
| **与元认知的关系** | 元认知（第2章 EP-P0-2）教"监控自己的思维"，思维模型教"有哪些思维工具可用"。两者是"监控能力+工具库"的关系 |

**核心矛盾**：当前系统假设"教了知识点→学生会解题"，但中间缺了"思维方法"这一环。

### 4.2 10大核心思维模型

#### 4.2.1 逆向思维（执果索因）

- **核心思想**：从问题要求的结果出发，倒推需要什么条件
- **适用场景**：应用题、证明题、"求什么"类问题
- **使用步骤**：①明确要求什么 ②要得到这个结果需要先知道什么 ③一步步倒推到已知条件
- **教学引导语**：
  - "题目要我们求什么？要求出这个，需要先知道什么？"
  - "我们从结果倒着想，要得到这个答案，上一步应该是什么？"
  - "如果答案是X，那它必须满足什么条件？"
- **典型例题**：几何证明（要证平行→需要同位角相等→需要三角形全等→…）
- **常见错误**：倒推到一半就跳步、倒推路径不唯一时没有考虑所有可能

#### 4.2.2 图形化思维（数形结合）

- **核心思想**：把抽象的数量关系转化为图形，或用代数方法解决几何问题
- **适用场景**：函数、不等式、行程问题、几何、最值问题
- **使用步骤**：①判断能否画图 ②画图标注已知条件 ③从图形中找关系 ④转回代数表达
- **教学引导语**：
  - "这道题我们画个图看看？把已知的标上去，看看能不能看出关系"
  - "如果把这个式子画成图，会长什么样？"
  - "图上哪一段代表我们要求的量？"
- **典型例题**：行程问题画线段图、函数图像分析、不等式解集在数轴上表示
- **常见错误**：图画得不标准导致误判、画图时漏标条件、只画图不转回代数

#### 4.2.3 问题拆分（分而治之）

- **核心思想**：把复杂问题拆成若干简单子问题，逐个解决
- **适用场景**：综合题、多条件问题、看起来"很难"的题
- **使用步骤**：①通读全题 ②列出所有已知条件和要求 ③判断可以分成几步 ④第一步解决什么 ⑤逐步推进
- **教学引导语**：
  - "这道题看起来有点吓人，我们把它拆成小步。第一步先做什么？"
  - "题目里有几个条件？我们一个一个来处理"
  - "先不管最后答案，我们先把能求的求出来"
- **典型例题**：有理数混合运算（先算乘方→再乘除→后加减）、综合应用题
- **常见错误**：拆分时跳步、子问题之间的关系没理清、拆得太碎反而混乱
- **与工作记忆的关系**：拆分后每步都在工作记忆容量内，降低认知负荷

#### 4.2.4 类比思维（模式识别）

- **核心思想**：找到当前问题与已解决问题的相似结构，迁移解法
- **适用场景**：变式题、新题型、"没见过"的题
- **使用步骤**：①这道题和之前做过的哪道题像？②相同的结构是什么？③不同的地方在哪？④能否套用类似方法？
- **教学引导语**：
  - "这道题让你想起之前做过的哪道题？它们哪里像？"
  - "我们之前做过一道类似的，还记得是怎么做的吗？"
  - "这道题和那道题有什么不一样的地方？方法需要调整吗？"
- **典型例题**：变式题（换数字/换情境但结构相同）、新题型转化为旧题型
- **常见错误**：只看表面相似不看结构、生搬硬套不调整、忽略关键差异
- **与元认知的关系**：需要学生主动检索已有知识，是元认知"计划"环节的核心能力

#### 4.2.5 转化思维（化归）

- **核心思想**：把未知问题转化为已知问题，把复杂形式转化为简单形式
- **适用场景**：换元法、配方法、几何变换、方程变形、因式分解
- **使用步骤**：①这个问题能不能变成我会的形式？②做什么变换可以简化？③转化后解决 ④转化回原问题
- **教学引导语**：
  - "这个形式看起来复杂，我们能不能做个变换让它简单一点？比如设y=..."
  - "如果把它变成我们学过的形式，会是什么样？"
  - "这一步我们做了什么变换？为什么可以这样变？"
- **典型例题**：换元法解方程、配方法、几何平移/旋转、分式化简
- **常见错误**：变换后忘记变回来、变换的等价性没验证、过度变换反而复杂

#### 4.2.6 分类讨论（不重不漏）

- **核心思想**：当问题有多种可能情况时，分情况讨论，确保不重复不遗漏
- **适用场景**：绝对值、参数方程、几何位置关系、排列组合、分段函数
- **使用步骤**：①有几种可能情况？②分类标准是什么？③每种情况分别解决 ④检查是否覆盖所有情况
- **教学引导语**：
  - "这道题有没有可能分几种情况？我们先想想有哪几种，再一种一种来"
  - "绝对值里面的数可能是正的也可能是负的，我们分开讨论好不好？"
  - "分完了吗？有没有漏掉什么情况？有没有重复的？"
- **典型例题**：绝对值方程/不等式、含参数方程、几何图形位置关系
- **常见错误**：漏掉某种情况、分类标准不统一导致重复、分完后没有综合结论

#### 4.2.7 极端思维（特殊值/边界）

- **核心思想**：考虑极端情况（最大值、最小值、边界、特殊值）来快速判断或验证
- **适用场景**：选择题、填空题、估算、验证答案、找规律、排除法
- **使用步骤**：①取一个特殊值/极端情况 ②在这个情况下结果是什么？③能否推广到一般情况？
- **教学引导语**：
  - "我们试试取个特殊值，比如让x=0，看看会怎么样？"
  - "如果这个数特别大/特别小，会发生什么？"
  - "我们用边界情况检验一下答案对不对"
- **典型例题**：选择题排除法、估算结果范围、验证公式正确性
- **常见错误**：把特殊情况当成一般结论、特殊值选得不够极端、用极端思维替代严格证明
- **注意**：极端思维用于启发和验证，不能替代严格证明（解答题必须完整推导）

#### 4.2.8 整体思维（整体代入）

- **核心思想**：不从局部入手，把某个复杂部分看作一个整体来处理
- **适用场景**：换元法、整体代入、代数式求值、几何整体面积、方程组整体加减
- **使用步骤**：①有没有一个复杂的部分反复出现？②把它看作一个整体 ③先求整体的值 ④再求局部
- **教学引导语**：
  - "这个式子反复出现，我们把它看作一个整体，设它为t，看看会不会简单点"
  - "不用急着把每个量都求出来，我们看看能不能整体代入"
  - "如果把这两个方程加在一起/减一减，会怎么样？"
- **典型例题**：已知x+y=3求x²+2xy+y²、整体换元、几何阴影面积
- **常见错误**：看不出哪个部分可以看作整体、整体求值后忘记求局部、整体和局部的关系没理清

#### 4.2.9 建模思维（数学抽象）

- **核心思想**：把实际问题中的数量关系抽象为数学模型（方程、函数、不等式、几何图形）
- **适用场景**：应用题、实际问题、跨学科问题、开放题
- **使用步骤**：①问题中有哪些量？②量之间有什么关系？③用什么数学模型表达？④解模型 ⑤检验是否符合实际
- **教学引导语**：
  - "这道题在说一件什么事？里面有哪些量？它们之间是什么关系？"
  - "我们能不能用方程把这个关系写出来？"
  - "解出来了，这个答案符合实际情况吗？"
- **典型例题**：行程问题、工程问题、利润问题、增长率问题
- **常见错误**：找错等量关系、单位不统一、解完不检验是否符合实际、设未知数不清晰

#### 4.2.10 检验思维（验证反思）

- **核心思想**：做完题后主动检验答案是否正确、是否合理、是否完整
- **适用场景**：所有题目，尤其是计算题、应用题、证明题
- **使用步骤**：①代入验证 ②估算是否合理 ③检查是否有遗漏情况 ④反思用了什么方法
- **教学引导语**：
  - "做完了？我们来检验一下。把答案代回去看看对不对？"
  - "这个结果合理吗？估算一下大概应该在什么范围？"
  - "再想想有没有漏掉什么情况？用了什么方法？下次遇到类似题还能用吗？"
- **典型例题**：方程解的代入检验、应用题结果的合理性判断、分类讨论的完整性检查
- **常见错误**：做完不检查、只检查计算不检查思路、检验方法单一
- **与元认知的关系**：检验是元认知"监控+评估"环节的核心能力

```python
    if not node or not node.common_thinking_models:
        return ""
    # 过滤掉学生已经熟练的模型，只提示薄弱的
    weak_models = [
        mid for mid in node.common_thinking_models
        if student.thinking_model_mastery.get(mid, 0.0) < 0.6
    ]
    if not weak_models:
        return ""
    import random
    hints = []
    for mid in weak_models[:2]:  # 最多提示2个模型
        model = THINKING_MODELS.get(mid)
        if model:
            hints.append(f"- 本题适合用{model.name}：{random.choice(model.教学引导语)}")
    return "## 本题思维方法引导\n" + "\n".join(hints)
```

**关键设计原则**：
- 不是直接告诉学生"用逆向思维"，而是用引导语让学生自己走出来
- 只提示学生薄弱的模型，已经熟练的不重复提示
- 每轮最多提示2个，避免信息过载
- 提示语随机选择，避免学生形成固定套路

| 行为 | 掌握度变化 | 评估块字段 |
|------|-----------|-----------|
| 学生主动使用某思维模型（"我们画图看看""从结果倒推"） | +0.05 | `student_initiated_model: "visualization"` |

| 用某模型独立解出题 | +0.08 | `used_model_success: "analogy"` |
| 用某模型但出错了 | +0.01（尝试了就鼓励） | `used_model_failed: "case_analysis"` |

```python
def update_thinking_model_mastery(student: Student, eval_data: dict) -> None:
    mastery = student.thinking_model_mastery
    
    # 学生主动使用
    if eval_data.get("student_initiated_model"):
        mid = eval_data["student_initiated_model"]
        mastery[mid] = min(1.0, mastery.get(mid, 0.0) + 0.05)
    
    # 需要提示才使用
    if eval_data.get("prompted_model"):
        mid = eval_data["prompted_model"]
        mastery[mid] = min(1.0, mastery.get(mid, 0.0) + 0.02)
    
    # 错过了应该使用的模型
    if eval_data.get("missed_model"):
        mid = eval_data["missed_model"]
        mastery[mid] = max(0.0, mastery.get(mid, 0.0) - 0.03)
    
    # 独立使用成功
    if eval_data.get("used_model_success"):
        mid = eval_data["used_model_success"]
        mastery[mid] = min(1.0, mastery.get(mid, 0.0) + 0.08)
```

## 5. 内容安全与未成年人保护

> 本章是面向 K12 学生的 AI 应用的底线。当前系统完全没有内容安全机制，LLM 输出直接展示给学生，学生数据明文存储，存在多重风险。

### 5.1 为什么必须有

| 风险维度 | 当前状态 | 潜在后果 |
|---------|---------|---------|
| **LLM 输出安全** | 无过滤，LLM 输出直接展示 | 可能输出不适合未成年人的内容（暴力、色情、敏感话题、负面心理暗示） |
| **心理危机识别** | 无识别，学生说"不想活了"也继续讲数学题 | 错过心理危机干预时机，严重后果 |
| **API Key 安全** | 明文存储在 `data/config.json` | 本地应用被他人使用时 Key 泄露，产生费用/滥用 |
| **学生数据隐私** | 情绪记录、学习弱点、对话历史全部明文 JSON | 未成年人隐私泄露，涉及敏感个人信息 |
| **防沉迷** | 无时长上限、无休息强制、无夜间限制 | 学生过度使用，影响视力和作息 |
| **敏感话题** | 无专门处理策略 | 学生问到政治/宗教/性别等敏感话题时，LLM 可能输出不当内容 |
| **家长监护** | 无家长端、无学习报告、无内容过滤设置 | 家长无法了解学习情况，无法设置保护等级 |

### 5.2 LLM 输出内容过滤层

新增 `backend/services/content_filter.py`，在 LLM 输出后、展示给学生前加一层审核：

```python
class ContentFilter:
    """内容安全过滤：在 LLM 输出展示给学生前审核。"""

    # 不适合未成年人的关键词（需根据实际情况扩展）
    INAPPROPRIATE_KEYWORDS = [
        "暴力", "血腥", "色情", "淫秽", "自杀", "自残",
        "毒品", "赌博", "恐怖", "极端", "歧视",
    ]

    # 敏感话题（需要专门引导策略，不是简单拦截）
    SENSITIVE_TOPICS = {
        "politics": ["政治", "政府", "国家", "选举", "政党"],
        "religion": ["宗教", "信仰", "神", "佛", "上帝"],
        "gender": ["性别", "同性恋", "跨性别", "性取向"],
        "violence": ["打架", "欺负", "校园暴力", "霸凌"],
    }

    def filter_output(self, text: str, context: dict) -> tuple[str, bool]:
        """过滤 LLM 输出，返回 (过滤后文本, 是否触发过滤)。"""
        # 1. 检查不适合内容
        for kw in self.INAPPROPRIATE_KEYWORDS:
            if kw in text:
                return self._safe_response(), True

        # 2. 检查敏感话题，转用专门引导
        for topic, keywords in self.SENSITIVE_TOPICS.items():
            if any(kw in text for kw in keywords):
                return self._sensitive_topic_response(topic), True

        return text, False

    def _safe_response(self) -> str:
        return "这个话题我们暂时不聊哦～有什么数学题想一起看看吗？🌸"

    def _sensitive_topic_response(self, topic: str) -> str:
        responses = {
            "politics": "这个话题比较复杂，等你长大一些我们再深入讨论好不好？现在先专注数学～",
            "religion": "信仰是很个人的事情，每个人都有自己的选择，我们尊重就好～",
            "gender": "每个人都是独特的，尊重自己和他人就好～有什么数学问题吗？",
            "violence": "遇到这种事情一定要告诉家长和老师哦，保护好自己最重要！",
        }
        return responses.get(topic, self._safe_response())
```

在 `chat.py` 的 `process_message` 中，LLM 输出后、yield 前调用过滤：

```python
if triggered:
```


#### 5.3.2 危机干预流程

```python
def detect_crisis(message: str) -> str | None:
    """检测心理危机，返回危机等级或 None。"""
    for level, keywords in CRISIS_KEYWORDS.items():
        if any(kw in message for kw in keywords):
            return level
    return None

def crisis_intervention(level: str, student: Student) -> str:
    """心理危机干预：根据等级给出专门回应，而非继续教学。"""
    if level == "severe":
        return (
            "听到你说这些，我很担心你🫂 你现在安全吗？"
            "如果你觉得很难受，一定要告诉爸爸妈妈或者打心理援助热线好吗？"
            "全国心理援助热线：400-161-9995，随时有人接。"
            "你不是一个人，我们一起面对好不好？"
        )
    elif level == "moderate":
        return (
            "听起来你最近好累呀🫂 能跟我说说发生了什么吗？"
            "有时候说出来就会好一些。不想说也没关系，我们今天就不做题了，"
            "想聊什么都可以～"
        )
    elif level == "bullying":
        return (
            "被欺负不是你的错！🫂 一定要告诉爸爸妈妈和老师，"
            "他们会保护你的。你愿意跟我详细说说吗？"
        )
    elif level == "family":
        return (
            "家里的事情让你心烦了吧🫂 大人的事情有时候很复杂，"
            "不是你的错。今天我们就不做题了，想聊聊吗？"
        )
    return ""
```

在 `chat.py` 的 `process_message` 开头，先检测危机：

```python
async def process_message(student, user_message, ...):

            "level": crisis_level,
            "message": user_message[:200],

        get_storage().save(student)

        yield {"type": "text", "content": response}
        return
    # ... 正常教学流程
```

```python
def check_time_limit(student: Student) -> str | None:
    """检查是否超过时长限制，返回提示或 None。"""
    today = student.today_iso()
    today_minutes = sum(
        h.duration_minutes for h in student.session_history if h.date == today
```

## 6. 数据迁移与版本兼容

> 本文档提出了大量数据模型变更（CognitiveProfile、thinking_model_mastery、crisis_events 等）。当前系统没有数据迁移机制，模型变更后旧数据会加载失败。

### 6.1 当前问题

| 问题 | 说明 |
|------|------|
| **无版本号** | `Student` 模型没有 `schema_version` 字段，无法判断数据是哪个版本的 |
| **直接反序列化** | `storage.py:46` 直接 `Student.model_validate_json(f.read())`，新增字段如果没有默认值会报错 |
| **无迁移脚本** | 模型变更后没有自动迁移逻辑 |
| **无备份机制** | 迁移前不备份，迁移失败数据丢失 |
| **向前兼容差** | 旧版本代码读取新版本数据可能失败 |

### 6.2 版本号设计

在 `Student` 模型中增加版本号：

```python
class Student(BaseModel):
    # ... 现有字段 ...
    schema_version: int = 1  # 数据模型版本号
```

**版本规划**：

| 版本 | 变更内容 |
|------|---------|
| v1 | 当前版本（无 CognitiveProfile、无 thinking_model_mastery、无 crisis_events） |
| v2 | 增加 CognitiveProfile、thinking_model_mastery、crisis_events、schema_version |
| v3 | 未来变更（如分领域认知水平、家长设置等） |

### 6.3 迁移框架设计

新增 `backend/services/migration.py`：

```python
"""数据迁移框架：处理不同版本学生档案的自动升级。"""

import json
import shutil
from pathlib import Path
from typing import Callable

CURRENT_VERSION = 2

# 迁移函数注册表：{目标版本: 迁移函数}
MIGRATIONS: dict[int, Callable[[dict], dict]] = {}


def migration(target_version: int):
    """装饰器：注册迁移函数。"""
    def decorator(func):
        MIGRATIONS[target_version] = func
        return func
    return decorator


def migrate_student_data(data: dict, student_path: Path) -> dict:
    """迁移学生数据到最新版本。"""
    current = data.get("schema_version", 1)

    if current == CURRENT_VERSION:
        return data

    # 迁移前备份
    backup_path = student_path.with_suffix(f".v{current}.bak")
    if not backup_path.exists():
        shutil.copy2(student_path, backup_path)

    # 逐步迁移
    for version in range(current + 1, CURRENT_VERSION + 1):
        if version in MIGRATIONS:
            data = MIGRATIONS[version](data)
            data["schema_version"] = version

    return data


# ---------------------------------------------------------------------------
# 迁移函数实现
# ---------------------------------------------------------------------------

@migration(2)
def migrate_v1_to_v2(data: dict) -> dict:
    """v1 → v2：增加认知画像、思维模型掌握度、危机事件。"""
    # 增加 CognitiveProfile（默认值）
    if "cognitive_profile" not in data:
        data["cognitive_profile"] = {
            "cognitive_stage": "concrete",
            "working_memory_capacity": "medium",
            "abstract_thinking": 0.3,
            "metacognition_level": 0.2,
            "executive_function": {"inhibition": 0.5, "flexibility": 0.4},
            "math_anxiety": 0.2,
            "anxiety_triggers": [],
            "learning_preference": "visual",
            "domain_levels": {},
            "assessed_at": "",
            "last_updated": "",
            "assessment_confidence": 0.0,
        }

    # 增加思维模型掌握度
    if "thinking_model_mastery" not in data:
        data["thinking_model_mastery"] = {}

    # 增加危机事件记录
    if "crisis_events" not in data:
        data["crisis_events"] = []

    return data
```

### 6.4 集成到存储层

修改 `backend/services/storage.py` 的 `load` 方法：

```python
def load(self, student_id: str) -> Student | None:
    path = self._path(student_id)
    if not path.exists():
        return None
    with open(path, encoding="utf-8") as f:
        raw = json.load(f)

    # 迁移到最新版本
    from backend.services.migration import migrate_student_data, CURRENT_VERSION
    migrated = migrate_student_data(raw, path)

    # 如果发生了迁移，保存迁移后的数据
    if migrated.get("schema_version", 1) != raw.get("schema_version", 1):
        with open(path, "w", encoding="utf-8") as f:
            json.dump(migrated, f, ensure_ascii=False, indent=2)

    return Student.model_validate_json(json.dumps(migrated, ensure_ascii=False))
```

### 6.5 向前兼容策略

| 策略 | 说明 |
|------|------|
| **新字段必须有默认值** | Pydantic 模型中所有新增字段都有 `default` 或 `default_factory`，旧数据缺少字段时用默认值填充 |
| **不删除旧字段** | 废弃字段保留但标记为 deprecated，不直接删除，避免旧代码读取新数据失败 |
| **枚举值只增不减** | `Literal` 类型的字段，新增取值可以，不要删除旧取值 |
| **版本号判断** | 代码中根据 `schema_version` 判断是否使用新功能，旧版本数据走兼容逻辑 |

```python
import sympy as sp
from typing import Any

def evaluate_expression(expr_str: str, substitutions: dict[str, float] | None = None) -> dict[str, Any]:
    """解析并计算数学表达式，返回精确结果和数值近似。"""
    expr = sp.sympify(expr_str)
    if substitutions:
        expr = expr.subs(substitutions)
    return {
        "exact": str(expr),
        "numeric": float(expr.evalf()) if expr.is_number else None,
        "latex": sp.latex(expr),
    }

def solve_equation(eq_str: str, symbol: str = "x") -> dict[str, Any]:
    """解方程，返回所有解。"""
    x = sp.Symbol(symbol)
    eq = sp.sympify(eq_str)
    solutions = sp.solve(eq, x)
    return {
        "solutions": [str(s) for s in solutions],
        "latex": [sp.latex(s) for s in solutions],
    }

def simplify_expression(expr_str: str) -> dict[str, Any]:
    """化简表达式。"""
    expr = sp.simplify(sp.sympify(expr_str))
    return {"result": str(expr), "latex": sp.latex(expr)}

def derivative(expr_str: str, symbol: str = "x") -> dict[str, Any]:
    """求导。"""
    x = sp.Symbol(symbol)
    result = sp.diff(sp.sympify(expr_str), x)
    return {"result": str(result), "latex": sp.latex(result)}
```

```javascript
/**
 * 将文本中的 LaTeX 公式渲染为 HTML。
 * 支持：$...$（行内公式）、$$...$$（块级公式）
 * 非公式部分进行 HTML 转义。
 */
function renderMathText(text) {
  if (!text) return '';
  
  // 先提取所有公式，占位保护
  const formulas = [];
  let protectedText = text;
  
  // 块级公式 $$...$$
  protectedText = protectedText.replace(/\$\$([\s\S]+?)\$\$/g, (match, formula) => {
    formulas.push({ formula, display: true });
    return `__FORMULA_${formulas.length - 1}__`;
  });
  
  // 行内公式 $...$
  protectedText = protectedText.replace(/\$([^\n$]+?)\$/g, (match, formula) => {
    formulas.push({ formula, display: false });
    return `__FORMULA_${formulas.length - 1}__`;
  });
  
  // 转义非公式部分的 HTML
  let html = escapeHtml(protectedText);
  
  // 还原公式并渲染
  formulas.forEach((item, idx) => {
    const placeholder = `__FORMULA_${idx}__`;
    try {
      const rendered = katex.renderToString(item.formula, {
        throwOnError: false,
        displayMode: item.display,
        output: 'html',
      });
      html = html.replace(placeholder, rendered);
    } catch (e) {
      // 渲染失败时显示原始公式文本
      html = html.replace(placeholder, `<code>${escapeHtml(item.formula)}</code>`);
    }
  });
  
  return html;
}
```

### P0-4："假流式"输出 — 用户等待完整回复后才看到文字

**严重程度**：🔴 高 — 体验差，用户以为卡住了

**问题位置**：
- `backend/services/llm.py:56-74` — `stream_chat` 函数

**问题描述**：

注释说是为了"避免SDK内部生成器跨挂起点产生清理异常"，但实际效果是：用户发送消息后，要等**整个回复（含评估块）全部生成完毕**，才开始看到文字以固定节奏出现。这不是真正的流式输出，而是"延迟批量输出"。

对于数学题的分步讲解，回复可能较长，用户等待时间可达 5-10 秒，期间界面只有一个打字动画点，容易以为卡住了。

**改进方案**：

实现真正的逐字流式输出。评估块可以在流结束后单独解析，正文部分实时推送：

```python
async def stream_chat(system_prompt, history, user_message):
    messages = [{"role": "system", "content": system_prompt}, *history]
    if user_message:
        messages.append({"role": "user", "content": user_message})

    response = await get_client().chat.completions.create(
        model=DEEPSEEK_MODEL,
        messages=messages,
        temperature=LLM_TEMPERATURE,
        max_tokens=LLM_MAX_TOKENS,
        stream=True,
    )

    accumulated = []
    eval_started = False
    eval_buffer = []
    
    try:
        async for chunk in response:
            delta = chunk.choices[0].delta if chunk.choices else None
            content = getattr(delta, "content", None) if delta else None
            if not content:
                continue
            
            accumulated.append(content)
            
            # 检测评估块开始标记
            if EVAL_MARKER_START in "".join(accumulated[-20:]):
                eval_started = True
                # 把已经 yield 的评估块标记部分撤回（需要缓冲）
                continue
            
            if eval_started:
                eval_buffer.append(content)
            else:
                # 真正的逐字流式输出
                yield {"type": "text", "content": content}
    finally:
        await response.close()

    # 流结束后解析评估块
    full_text = "".join(accumulated)
    _, eval_data = parse_reply(full_text)
    if eval_data is not None:
        yield {"type": "eval", "data": eval_data}
```

### P1-2：前置依赖链只追踪第一个前置

**问题位置**：`backend/knowledge/syllabus.py:796-806`

**问题描述**：
```python

    current = node_id
    while current and current not in visited:
        visited.add(current)
```

比如"有理数混合运算"（`6a_hunhe`）有6个前置（加减乘除乘方运算律），只追踪第一个会漏掉关键依赖。补漏时找不到真正的"最小不会单元"，违背了设计方案中"沿依赖链回溯找最小不会单元"的理念。

**改进方案**：
```python
def prerequisite_chain(node_id):
    """返回所有前置依赖节点（含自身），BFS 遍历完整依赖图。"""
    chain = []
    visited = set()
    queue = [node_id]
    while queue:
        current = queue.pop(0)
        if current in visited:
            continue
        visited.add(current)
        node = BY_ID.get(current)
        if node:
            chain.append(current)
            queue.extend(node.prerequisites)
    return list(reversed(chain))  # 最基础的在前

def find_minimum_gap_node(node_id, mastery):
    """找到依赖链中掌握度最低的节点（最小不会单元）。"""
    chain = prerequisite_chain(node_id)
    weakest = min(chain, key=lambda nid: mastery.get(nid, 0.0))
    return weakest
```

**验收标准**：
- [ ] `prerequisite_chain` 返回所有前置依赖，不只是第一个
- [ ] 新增 `find_minimum_gap_node` 函数，用于补漏时定位最小不会单元
- [ ] `chat.py` 中补漏逻辑使用新函数

### P1-4：掌握度更新完全信任 LLM，无客观约束

**问题位置**：`backend/agent/assessment.py:19-22`

**问题描述**：
```python

for topic_id, score in mastery_updates.items():
    if syllabus.get_node(topic_id) and isinstance(score, (int, float)):
        student.mastery[topic_id] = max(0.0, min(1.0, float(score)))
        # 直接覆盖！没有增量、没有衰减、没有验证
```

问题：
1. **直接覆盖**：LLM 说 0.8 就变成 0.8，不管之前是 0.2 还是 0.9
2. **无验证**：学生是否真的答对了，没有经过计算工具验证
3. **无衰减**：长时间不复习的知识点不会自然遗忘
4. **无上下界约束**：第一次接触就可能给 0.8

**改进方案**：
```python
def apply_eval(student, eval_data):
    mastery_updates = eval_data.get("mastery_updates") or {}
    verified = eval_data.get("verified_answer", False)  # 是否经过计算验证
    
    for topic_id, score in mastery_updates.items():
        if not syllabus.get_node(topic_id) or not isinstance(score, (int, float)):
            continue
        
        old_score = student.mastery.get(topic_id, 0.0)
        new_score = float(score)
        
        # 增量更新：LLM 评估占 30% 权重，历史占 70%
        # 经过计算验证时，LLM 评估权重提升到 50%
        weight = 0.5 if verified else 0.3
        updated = old_score * (1 - weight) + new_score * weight
        
        # 单轮最大变化幅度限制（防止跳变）
        max_delta = 0.3 if verified else 0.15
        delta = max(-max_delta, min(max_delta, updated - old_score))
        student.mastery[topic_id] = max(0.0, min(1.0, old_score + delta))

# 新增：遗忘衰减（在会话开始时调用）
def apply_forgetting_decay(student):
    """基于距离上次学习的时间，对掌握度进行艾宾浩斯衰减。"""
    from datetime import datetime, timedelta
    today = datetime.now().date()
    
    for topic_id, score in list(student.mastery.items()):
        # 查找该知识点最后学习时间
        last_studied = _find_last_study_date(student, topic_id)
        if not last_studied:
            continue
        
        days_since = (today - last_studied).days
        if days_since <= 1:
            continue
        
        # 艾宾浩斯遗忘曲线：R = e^(-t/S)，S 为记忆强度
        memory_strength = score * 10 + 1  # 掌握度越高，记忆越强
        retention = math.exp(-days_since / memory_strength)
        student.mastery[topic_id] = round(score * retention, 2)
```

**验收标准**：
- [ ] 掌握度采用增量更新，不直接覆盖
- [ ] 单轮掌握度变化有最大幅度限制
- [ ] 经过计算验证的答题，掌握度提升权重更高
- [ ] 长时间不复习的知识点有遗忘衰减
- [ ] 掌握度变化可追溯（记录历史值）

#### V-P0-1: 内容过滤时序修复 — 先过滤再输出

**问题定位**：`backend/agent/chat.py:217-223` 内容过滤在 LLM 流式输出**之后**才执行。用户已经实时看到了不适合内容，然后才被追加一条更正消息。这是严重的安全时序问题——不适合内容已经暴露给未成年人。

**当前流程**：
1. LLM 流式输出 → 逐字 yield 给前端（用户实时看到）
2. 流结束后 → 调用 `filter_llm_output` 过滤
3. 如果触发过滤 → 追加一条更正消息（但原文已被看到）

**实现方案**：改为"缓冲-过滤-模拟流式输出"模式。
1. LLM 流式输出时，后端只缓冲完整内容，**不输出给前端**
2. 流结束后，对完整正文进行内容过滤
3. 过滤通过后，再模拟逐字输出给前端（每 3 个字符一次 yield，间隔 10ms）
4. 如果触发过滤，直接输出过滤后的安全回应（同样模拟逐字）

#### V-P0-2: Function Calling 强制 — 后端计算验证层

**问题定位**：`backend/services/llm.py` 依赖 LLM **自觉**调用计算器。如果 LLM 应该算但没调用工具（Function Calling 不触发），就直接心算给答案，可能算错。`backend/agent/persona.py:56` 写了"必须调用计算工具"，但这只是 prompt 要求，没有后端强制机制。LLM 不遵守时无法兜底。

**实现方案**：增加"计算后验证"层。LLM 返回回复后，用正则提取回复中的所有数学等式（如 `x = 3`、`2+3 = 5`、`答案是42`），用 SymPy 重新计算验证。如果不一致，自动替换为正确结果，并在日志中记录警告。

**代码修改** — 新增 `backend/services/calc_verifier.py`：

```python
"""计算结果验证器：LLM回复中的数学等式用SymPy重新验证，不一致则自动替换。

这是 Function Calling 的兜底机制：即使 LLM 没有调用计算工具，
后端也会验证所有数学结果，保证教给学生的计算一定正确。
"""

import re
import logging

import sympy as sp

logger = logging.getLogger(__name__)

# 匹配数学等式模式
# 模式1：变量 = 数值（如 x = 3, y = -2.5）
VAR_EQ = re.compile(r'([a-zA-Z_][a-zA-Z0-9_]*)\s*=\s*(-?\d+\.?\d*)')
# 模式2：算术表达式 = 数值（如 2+3 = 5, (3+4)*2 = 14）
EXPR_EQ = re.compile(r'([\d\+\-\*\/\(\)\.\s]+?)\s*=\s*(-?\d+\.?\d*)')


def verify_and_fix(text: str) -> tuple[str, list[dict]]:
    """验证文本中的数学等式，返回(修正后文本, 修正记录列表)。"""
    fixes = []

    def _try_fix(expr_str: str, claimed: str, full_match: str) -> str:
        """尝试验证一个等式，返回修正后的完整匹配或原匹配。"""
        try:
            expr = sp.sympify(expr_str.strip())
            if expr.is_number:
                actual = float(expr.evalf())
                claimed_val = float(claimed)
                if abs(actual - claimed_val) > 0.001:
                    fixes.append({
                        "original": full_match,
                        "expr": expr_str.strip(),
                        "claimed": claimed,
                        "actual": actual,
                    })
                    return f"{expr_str.strip()} = {actual:g}"
        except Exception:
            pass  # 解析失败，不修改
        return full_match

    # 验证变量等式
    def replace_var(match):
        return _try_fix(match.group(1), match.group(2), match.group(0))

    # 验证算术等式
    def replace_expr(match):
        return _try_fix(match.group(1), match.group(2), match.group(0))

    text = VAR_EQ.sub(replace_var, text)
    text = EXPR_EQ.sub(replace_expr, text)

    if fixes:
        logger.warning("计算验证修正了%d处: %s", len(fixes), fixes)

    return text, fixes
```

**验收标准**（✅ 已实现，兼容正确/错误/含未知数方程不误伤）：
- [x] LLM 给出错误计算结果时（如 `2+3 = 6`），后端自动修正为 `2+3 = 5`
- [x] 正确的计算结果不被修改
- [x] 修正记录写入日志（WARNING 级别）
- [x] 数学表达式解析失败时不破坏原文
- [x] 变量等式（如 `x = 4`）不误伤；含未知数方程（如 `3x+7=22`）不误伤

```python
"""心理危机识别与干预：面向 K12 学生的安全底线。

三级分类：
- severe: 严重危机词 → 直接触发干预
- moderate: 中度风险词 → 需上下文（连续消极≥2轮）才触发
- support: 欺凌/家庭问题 → 关怀流程，不是危机
- None: 轻度情绪或正常对话 → 走正常共情引导
"""

from typing import Any

# ===== 严重危机词（直接触发干预）=====
SEVERE_CRISIS_KEYWORDS = [
    "不想活", "不想活了", "活着没意思", "自杀", "自残",
    "想死", "结束生命", "活不下去", "不想活下去",
]

# ===== 中度风险词（需上下文判断，不直接触发）=====
MODERATE_RISK_WORDS = [
    "撑不住", "绝望", "一无是处", "觉得自己没用", "活着没意义",
]

# ===== 轻度情绪词（正常共情，不触发危机）=====
# 这些词在学生日常对话中频繁出现，不应触发危机干预
MILD_EMOTION_WORDS = [
    "好累", "好烦", "不想上学", "崩溃", "不想学", "好难",
    "烦死了", "累了", "困了", "饿了",
]

# ===== 支持关怀词（触发关怀流程，但不是危机）=====
SUPPORT_NEEDED_WORDS = {
    "bullying": ["被欺负", "被打", "被骂", "霸凌", "被孤立", "没人理我"],
    "family": ["爸妈吵架", "家暴", "爸妈离婚", "不想回家", "家里好烦", "爸爸妈妈不要我"],
}


def detect_crisis(message: str, context: dict[str, Any] | None = None) -> str | None:
    """检测心理危机，返回危机等级或 None。

    Args:
        message: 学生消息
        context: 上下文信息，支持:
            - consecutive_negative_turns: 连续消极轮次数

    Returns:
        "severe" | "moderate" | "support" | None
    """
    if not message:
        return None

    # 1. 严重词 → 直接触发
    for kw in SEVERE_CRISIS_KEYWORDS:
        if kw in message:
            return "severe"

    # 2. 中度词 → 需要上下文（连续消极≥2轮）
    has_moderate = any(kw in message for kw in MODERATE_RISK_WORDS)
    if has_moderate:
        consecutive = (context or {}).get("consecutive_negative_turns", 0)
        if consecutive >= 2:
            return "moderate"

    # 3. 欺凌/家庭 → support（关怀，不是危机）
    for keywords in SUPPORT_NEEDED_WORDS.values():
        if any(kw in message for kw in keywords):
            return "support"

    # 4. 轻度情绪或正常对话 → None（走正常共情）
    return None


def crisis_intervention(level: str) -> str:
    """心理危机干预：根据等级给出专门回应，而非继续教学。"""
    if level == "severe":
        return (
            "听到你说这些，我很担心你🫂 你现在安全吗？\n"
            "如果你觉得很难受，一定要告诉爸爸妈妈，或者打心理援助热线，"
            "随时都有人会接的。\n"
            "全国24小时心理援助热线：**400-161-9995**\n"
            "你不是一个人，我们一起面对好不好？🌸"
        )
    elif level == "moderate":
        return (
            "听起来你最近压力好大呀🫂 能跟我说说发生了什么吗？\n"
            "有时候说出来就会好一些。不想说也没关系，"
            "我们今天就不做题了，想聊什么都可以～"
        )
    elif level == "support":
        return (
            "遇到这种事情一定很难受吧🫂 能跟我详细说说吗？\n"
            "如果是被欺负或者家里的事，一定要告诉信任的大人哦，"
            "他们会帮你的。你不是一个人～"
        )
    return ""


def record_crisis(student, level: str, message: str) -> list[str]:
    """记录危机事件到学生档案，返回风险提醒。"""
    if not hasattr(student, "crisis_events"):
        student.crisis_events = []
    student.crisis_events.append({
        "date": student.today_iso(),
        "level": level,
        "message": message[:200],
    })

    risks = []
    if level == "severe":
        risks.append(f"⚠️ {student.name} 表达了严重心理危机信号，建议家长尽快关注并沟通。")
    elif level == "moderate":
        risks.append(f"⚠️ {student.name} 近期有持续情绪困扰，建议家长多关心陪伴。")
    elif level == "support":
        risks.append(f"ℹ️ {student.name} 提到了需要支持的情况（欺凌/家庭），建议关注。")
    return risks
```

```javascript
let voiceRecognition = null;
let isListening = false;

function initVoiceInput() {
  const btn = document.getElementById('btn-voice');
  if (!btn) return;

  // 检查浏览器支持
  const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition;
  if (!SpeechRecognition) {
    btn.style.display = 'none';  // 不支持则隐藏
    return;
  }

  voiceRecognition = new SpeechRecognition();
  voiceRecognition.lang = 'zh-CN';
  voiceRecognition.continuous = false;
  voiceRecognition.interimResults = true;

  voiceRecognition.onresult = (event) => {
    let transcript = '';
    for (let i = event.resultIndex; i < event.results.length; i++) {
      transcript += event.results[i][0].transcript;
    }
    document.getElementById('chat-input').value = transcript;
  };

  voiceRecognition.onend = () => {
    isListening = false;
    btn.classList.remove('listening');
  };

  voiceRecognition.onerror = (event) => {
    isListening = false;
    btn.classList.remove('listening');
    if (event.error !== 'no-speech' && event.error !== 'aborted') {
      toast('语音识别出了点问题，再试一次好吗？');
    }
  };

  btn.onclick = () => {
    if (isListening) {
      voiceRecognition.stop();
    } else {
      voiceRecognition.start();
      isListening = true;
      btn.classList.add('listening');
      toast('正在听你说…🎤');
    }
  };
}
```

```python
def generate_weekly_report(student: Student) -> dict:
    """生成本周学习报告。"""
    today = date.today()
    # 本周一

    # 上周一

        except (ValueError, TypeError):

    # 本周会话
    this_week = [
        s for s in student.session_history
        if _parse_date(s.date) and _parse_date(s.date) >= week_start
    ]
    # 上周会话
    last_week = [
        s for s in student.session_history
        if _parse_date(s.date) and last_week_start <= _parse_date(s.date) <= last_week_end
    ]

    # 统计
    this_minutes = sum(s.duration_minutes for s in this_week)
    last_minutes = sum(s.duration_minutes for s in last_week)

    this_days = len(set(s.date for s in this_week))
    last_days = len(set(s.date for s in last_week))

    this_badges = list(set(b for s in this_week for b in s.new_badges))

    # 掌握知识点数（mastery >= 0.7）
    mastered_count = sum(1 for v in student.mastery.values() if v >= 0.7)
    # 本周新掌握的（简化：取当前mastery中>=0.7的，无法精确区分本周新增）
    # 后续可以通过session_history的mastery快照精确计算

    return {
        "week_start": week_start.isoformat(),
        "week_end": today.isoformat(),
        "study_days": this_days,
        "study_minutes": this_minutes,
        "sessions_count": len(this_week),
        "new_badges": this_badges,
        "mastered_count": mastered_count,
        "open_gaps_count": len(student.open_gaps()),
        "streak_chain": student.streak_chain,
        # 对比上周
        "vs_last_week": {
            "minutes_delta": this_minutes - last_minutes,
            "days_delta": this_days - last_days,
            "sessions_delta": len(this_week) - len(last_week),
        }
    }
```
