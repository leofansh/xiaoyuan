## 二、P0 — 架构安全与确定性兜底

> P0 是必须优先做的，解决"系统可能崩溃/算错/误判危机"的生存级问题。

---

### A1. LLM 依赖过重，关键路径无确定性兜底

**问题描述**：状态转移、掌握度评估、漏洞识别、教学策略选择，全部依赖 LLM 输出的 `eval` 块。LLM 是概率性的，这意味着整个系统的行为不确定。

**违反的第一性原理**：公理3（LLM 输出不确定）+ 公理4（儿童不能判断 AI 对错）

**当前现状**：
- `chat.py` 中，LLM 返回的文本被解析为 `response` + `eval` 块
- `eval` 块中的 `state` 字段直接决定状态转移
- `eval` 块中的 `mastery_updates` 直接写入学生掌握度
- `eval` 块中的 `new_gaps` 直接添加漏洞
- 如果 LLM 不输出 eval 块，或输出格式错误，整个对话流程卡住

**详细实现方案**：

#### 1. 新建 `backend/agent/state_engine.py`（确定性状态转移规则引擎）

```python
"""确定性状态转移规则引擎。

LLM 的 eval 块从"指令"降级为"建议"，最终状态转移由本引擎的确定性规则决定。
规则优先级：确定性规则 > LLM 建议 > 默认保持当前状态。
"""

from typing import Optional, Tuple, List
from backend.models.student import Student, SessionState


# 合法状态列表
VALID_STATES = [
    "GREETING", "MOOD_CHECKIN", "MODE_SELECT", "PLAN",
    "BLIND_SPOT", "CORE_DERIVE", "EXAMPLE_CHECK", "ERROR_REVIEW",
    "OPTIONAL_VARIANT", "QUICK_REVIEW", "FIX_ONE_ERROR",
    "WEEKEND_CLEAR", "WRAP_UP", "DONE",
    # 新增状态
    "ANALOGY_EXPLANATION", "VISUALIZATION", "ERROR_ROOT_CAUSE",
    "BREAK_SUGGESTION",
]


class StateTransitionResult:
    def __init__(self, new_state: str, reason: str, confidence: float = 1.0):
        self.new_state = new_state
        self.reason = reason
        self.confidence = confidence  # 1.0=确定性规则, <1.0=LLM建议


def decide_next_state(
    student: Student,
    llm_suggested_state: Optional[str] = None,
    llm_suggested_mastery: Optional[dict] = None,
    consecutive_correct: int = 0,
    consecutive_wrong: int = 0,
    turn_count_in_state: int = 0,
) -> StateTransitionResult:
    """根据确定性规则决定下一个状态。

    规则优先级：
    1. 熔断规则（超时/连续错误）— 最高优先级
    2. 推进规则（连续正确/掌握度达标）
    3. 回退规则（连续错误/学生说不懂）
    4. LLM 建议（仅当确定性规则无明确结论时）
    5. 保持当前状态
    """
    current = student.current_session.state

    # 规则1：熔断 — 在同一状态停留过久
    if turn_count_in_state >= 8:
        return StateTransitionResult(
            "BREAK_SUGGESTION",
            f"在 {current} 状态停留 {turn_count_in_state} 轮，触发注意力熔断",
            confidence=1.0,
        )

    # 规则2：连续错误 — 回退或换策略
    if consecutive_wrong >= 3:
        if current == "EXAMPLE_CHECK":
            return StateTransitionResult(
                "CORE_DERIVE",
                "例题检查连续3次错误，回退到核心推导重新讲解",
                confidence=1.0,
            )
        if current == "CORE_DERIVE":
            return StateTransitionResult(
                "ANALOGY_EXPLANATION",
                "核心推导连续3次错误，切换到类比讲解",
                confidence=1.0,
            )

    # 规则3：连续正确 — 推进或跳过
    if consecutive_correct >= 2:
        if current == "BLIND_SPOT":
            return StateTransitionResult(
                "CORE_DERIVE",
                "漏洞诊断连续2次正确，推进到核心推导",
                confidence=1.0,
            )
        if current == "CORE_DERIVE":
            # 检查掌握度是否达标
            if llm_suggested_mastery:
                avg = sum(llm_suggested_mastery.values()) / len(llm_suggested_mastery)
                if avg >= 0.7:
                    return StateTransitionResult(
                        "EXAMPLE_CHECK",
                        f"核心推导掌握度 {avg:.2f} >= 0.7，推进到例题检查",
                        confidence=1.0,
                    )
            return StateTransitionResult(
                "EXAMPLE_CHECK",
                "核心推导连续2次正确，推进到例题检查",
                confidence=0.9,
            )
        if current == "EXAMPLE_CHECK":
            return StateTransitionResult(
                "OPTIONAL_VARIANT",
                "例题检查连续2次正确，推进到变式提升",
                confidence=1.0,
            )

    # 规则4：LLM 建议（仅验证合法性后采纳）
    if llm_suggested_state and llm_suggested_state in VALID_STATES:
        if llm_suggested_state != current:
            return StateTransitionResult(
                llm_suggested_state,
                f"采纳 LLM 建议：{current} → {llm_suggested_state}",
                confidence=0.6,
            )

    # 规则5：保持当前状态
    return StateTransitionResult(current, "无明确转移信号，保持当前状态", confidence=1.0)


def validate_state(state: str) -> bool:
    """验证状态是否合法。"""
    return state in VALID_STATES
```

#### 2. 新建 `backend/services/mastery_tracker.py`（贝叶斯掌握度更新）

```python
"""贝叶斯掌握度更新器。

不再让 LLM 直接决定掌握度数值，而是：
- LLM 只提供"学生本次答题是否正确"的判断
- 本模块根据答题结果 + 题目难度 + 历史表现，用贝叶斯更新计算掌握度
- 掌握度有置信度，随做题数增加而增加
"""

import math
from datetime import datetime, timedelta
from typing import Optional


class MasteryTracker:
    # 题目难度对应的"猜对概率"（越难，猜对概率越低，信息量越大）
    DIFFICULTY_GUESS_PROB = {1: 0.4, 2: 0.3, 3: 0.2, 4: 0.15, 5: 0.1}

    # 每周遗忘率（掌握度每周衰减比例）
    WEEKLY_DECAY_RATE = 0.08

    @staticmethod
    def update_mastery(
        prior_mastery: float,
        prior_confidence: float,
        is_correct: bool,
        difficulty: int = 3,
    ) -> tuple[float, float]:
        """贝叶斯更新掌握度。

        Args:
            prior_mastery: 先验掌握度 (0-1)
            prior_confidence: 先验置信度 (0-1)，基于历史做题数
            is_correct: 本次是否正确
            difficulty: 题目难度 (1-5)

        Returns:
            (后验掌握度, 后验置信度)
        """
        # 难度对应的猜对概率
        p_guess = MasteryTracker.DIFFICULTY_GUESS_PROB.get(difficulty, 0.2)

        # 如果掌握了，做对的概率高；如果没掌握，做对的概率=猜对概率
        p_correct_if_mastered = 0.9
        p_correct_if_not = p_guess

        # 贝叶斯更新
        if is_correct:
            numerator = prior_mastery * p_correct_if_mastered
            denominator = prior_mastery * p_correct_if_mastered + (1 - prior_mastery) * p_correct_if_not
        else:
            numerator = prior_mastery * (1 - p_correct_if_mastered)
            denominator = prior_mastery * (1 - p_correct_if_mastered) + (1 - prior_mastery) * (1 - p_correct_if_not)

        posterior = numerator / denominator if denominator > 0 else prior_mastery

        # 置信度更新：每做一道题，置信度增加，但有上限
        # 用等效样本量的思路：confidence = n / (n + k)
        prior_n = prior_confidence * 10 / (1 - prior_confidence) if prior_confidence < 1 else 100
        new_n = prior_n + 1
        new_confidence = min(0.95, new_n / (new_n + 10))

        return round(posterior, 4), round(new_confidence, 4)

    @staticmethod
    def apply_decay(mastery: float, last_updated_days: int) -> float:
        """应用遗忘曲线衰减。"""
        weeks = last_updated_days / 7.0
        decay_factor = (1 - MasteryTracker.WEEKLY_DECAY_RATE) ** weeks
        return round(mastery * decay_factor, 4)

    @staticmethod
    def estimate_zpd(mastery: float, confidence: float) -> str:
        """判断知识点是否在最近发展区。

        Returns:
            "ready" — 可以学习（ZPD内）
            "too_easy" — 已掌握，可跳过或做变式
            "too_hard" — 太难，需要先补前置
            "uncertain" — 置信度不足，需要先诊断
        """
        if confidence < 0.3:
            return "uncertain"
        if mastery >= 0.75:
            return "too_easy"
        if mastery < 0.25:
            return "too_hard"
        return "ready"
```

### A2. eval 块解析无容错

**问题描述**：LLM 输出的 eval 块格式不稳定（缺字段、JSON 语法错、标记缺失），当前解析代码直接 `json.loads`，失败时整个对话卡住。

**违反的第一性原理**：公理3（LLM 输出不确定）

**当前现状**：`chat.py` 中用正则提取 `<<<eval>>>` 块，然后 `json.loads`，无 try-catch 或字段默认值。

**详细实现方案**：

#### 新建 `backend/agent/eval_parser.py`

```python
"""eval 块解析器，带完整容错。

LLM 输出的 eval 块可能有各种格式问题，本模块确保：
- JSON 语法错误 → 尝试修复 → 失败则返回空 dict
- 缺失字段 → 用默认值填充
- 多余字段 → 忽略
- 类型错误 → 尝试转换 → 失败则用默认值
- 完全没有 eval 块 → 返回空 dict（不报错）
"""

import json
import re
from typing import Any, Optional


def extract_eval_block(text: str) -> Optional[str]:
    """从 LLM 输出中提取 eval 块内容。

    支持多种格式：
    - <<<eval>>>{"state": "CORE_DERIVE"}<<<END>>>
    - <<<eval>>>{"state": "CORE_DERIVE"}
    - ```json\n{"state": "CORE_DERIVE"}\n```
    - {"state": "CORE_DERIVE"} （纯 JSON，作为兜底）
    """
    # 格式1：<<<eval>>> ... <<<END>>>
    m = re.search(r'<<<eval\s*>>>(.*?)<<<\s*END\s*>>>', text, re.DOTALL)
    if m:
        return m.group(1).strip()

    # 格式2：<<<eval>>> ... （无结束标记，取到行尾或下一个空行）
    m = re.search(r'<<<eval\s*>>>(.*?)(?:\n\n|\Z)', text, re.DOTALL)
    if m:
        return m.group(1).strip()

    # 格式3：```json ... ```
    m = re.search(r'```(?:json)?\s*\n(.*?)```', text, re.DOTALL)
    if m:
        return m.group(1).strip()

    return None


def parse_eval(text: str) -> dict:
    """解析 eval 块，返回安全的 dict。

    任何解析失败都返回空 dict，不抛异常。
    """
    raw = extract_eval_block(text)
    if not raw:
        return {}

    # 尝试直接解析
    try:
        data = json.loads(raw)
        if isinstance(data, dict):
            return data
    except json.JSONDecodeError:
        pass

    # 尝试修复常见问题
    fixed = _repair_json(raw)
    if fixed:
        try:
            data = json.loads(fixed)
            if isinstance(data, dict):
                return data
        except json.JSONDecodeError:
            pass

    return {}


def _repair_json(raw: str) -> Optional[str]:
    """尝试修复常见 JSON 格式问题。"""
    s = raw.strip()

    # 去掉前后的非 JSON 字符
    s = re.sub(r'^[^{[]*', '', s)
    s = re.sub(r'[^}\]]*$', '', s)

    # 单引号转双引号
    s = s.replace("'", '"')

    # 去掉尾随逗号
    s = re.sub(r',\s*([}\]])', r'\1', s)

    # 未加引号的 key（如 {state: "CORE_DERIVE"}）
    s = re.sub(r'([{,]\s*)([a-zA-Z_][a-zA-Z0-9_]*)\s*:', r'\1"\2":', s)

    return s if s else None


def safe_get(data: dict, key: str, default: Any = None, expected_type: type = None) -> Any:
    """安全获取 eval 块字段，带类型检查和默认值。"""
    if key not in data:
        return default
    val = data[key]
    if expected_type and not isinstance(val, expected_type):
        # 尝试类型转换
        try:
            if expected_type == float:
                return float(val)
            if expected_type == int:
                return int(val)
            if expected_type == str:
                return str(val)
            if expected_type == bool:
                return bool(val)
        except (ValueError, TypeError):
            return default
    return val


def parse_eval_safe(text: str) -> dict:
    """解析 eval 块并标准化所有字段，返回带默认值的安全 dict。"""
    raw = parse_eval(text)
    return {
```

### A3. 计算验证层能力不足

**问题描述**：当前 `calc_verifier.py` 只能验证简单算术等式（如 `2+3=5`），无法验证方程每一步变形、应用题列式、几何计算等。

**违反的第一性原理**：公理4（儿童不能判断 AI 对错）+ 公理1（学习效果）

**当前现状**：正则匹配 `数字 运算符 数字 = 数字` 模式，SymPy 验证。不支持：
- 方程变形验证（如 `2x+5=13 → 2x=8`）
- 多步计算的中间结果
- 应用题的列式是否正确
- 几何公式计算
- 分数/小数混合运算

**详细实现方案**：

#### 增强 `backend/services/calc_verifier.py`

```python
"""增强版计算验证器。

支持：
1. 简单算术验证（已有）
2. 方程变形验证（新增）— 验证每一步方程变形是否等价
3. 表达式求值验证（新增）— 验证复杂表达式的计算结果
4. 单位一致性检查（新增）— 验证应用题单位是否一致
"""

import re
from typing import List, Tuple, Optional
import sympy as sp


class VerificationResult:
    def __init__(self, is_correct: bool, original: str, corrected: str = "", reason: str = ""):
        self.is_correct = is_correct
        self.original = original
        self.corrected = corrected
        self.reason = reason


def verify_equation_step(prev_eq: str, next_eq: str) -> VerificationResult:
    """验证方程变形是否等价（两边做了相同操作）。

    Args:
        prev_eq: 上一步方程，如 "2*x + 5 = 13"
        next_eq: 下一步方程，如 "2*x = 8"

    Returns:
        VerificationResult
    """
    try:
        # 解析两边
        prev_left, prev_right = _split_equation(prev_eq)
        next_left, next_right = _split_equation(next_eq)

        if prev_left is None or next_left is None:
            return VerificationResult(False, prev_eq, "", "无法解析方程")

        # 方法：检查 prev_eq 和 next_eq 是否有相同的解
        # 解方程
        x = sp.Symbol('x')
        prev_solutions = set(sp.solve(sp.Eq(prev_left, prev_right), x))
        next_solutions = set(sp.solve(sp.Eq(next_left, next_right), x))

        if prev_solutions == next_solutions:
            return VerificationResult(True, prev_eq, next_eq, "方程变形等价")
        else:
            # 尝试找出正确的下一步
            # 常见操作：两边减同一个数
            diff = prev_right - next_right
            if sp.simplify(prev_left - diff - next_left) == 0:
                correct_next = f"{sp.simplify(prev_left - diff)} = {next_right}"
                return VerificationResult(False, prev_eq, correct_next, f"方程变形不等价，正确应为 {correct_next}")

            return VerificationResult(False, prev_eq, "", "方程变形不等价")

    except Exception as e:
        return VerificationResult(False, prev_eq, "", f"验证出错: {e}")


def verify_expression(expr: str, expected: str) -> VerificationResult:
    """验证复杂表达式的计算结果。

    Args:
        expr: 表达式，如 "(3+4)*2"
        expected: 预期结果，如 "14"
    """
    try:
        actual = sp.sympify(expr)
        expected_val = sp.sympify(expected)
        if sp.simplify(actual - expected_val) == 0:
            return VerificationResult(True, f"{expr} = {expected}")
        else:
            return VerificationResult(False, f"{expr} = {expected}", f"{expr} = {actual}", "计算结果错误")
    except Exception as e:
        return VerificationResult(False, f"{expr} = {expected}", "", f"验证出错: {e}")


def verify_all_equations(text: str) -> List[VerificationResult]:
    """验证文本中所有的等式（简单算术 + 方程）。"""
    results = []

    # 简单算术（已有逻辑）
    arithmetic_pattern = r'(-?\d+(?:\.\d+)?)\s*([+\-*/])\s*(-?\d+(?:\.\d+)?)\s*=\s*(-?\d+(?:\.\d+)?)'
    for match in re.finditer(arithmetic_pattern, text):
        a, op, b, expected = match.groups()
        expr = f"{a}{op}{b}"
        results.append(verify_expression(expr, expected))

    # 方程（新增）— 匹配 "x = 数字" 形式
    equation_pattern = r'([a-zA-Z])\s*=\s*(-?\d+(?:\.\d+)?)'
    # 注意：这里只做简单的最终解验证，多步变形需要上下文

    return results


def _split_equation(eq: str) -> Tuple[Optional[sp.Expr], Optional[sp.Expr]]:
    """拆分方程为左右两边。"""
    if '=' not in eq:
        return None, None
    left_str, right_str = eq.split('=', 1)
    try:
        left = sp.sympify(left_str.strip())
        right = sp.sympify(right_str.strip())
        return left, right
    except Exception:
        return None, None


def verify_and_fix(text: str) -> Tuple[str, List[dict]]:
    """主入口：验证文本中的所有计算，修正错误。

    Returns:
        (修正后的文本, 修正记录列表)
    """
    fixes = []
    result_text = text

    all_results = verify_all_equations(text)
    for r in all_results:
        if not r.is_correct and r.corrected:
            fixes.append({
                "original": r.original,
                "corrected": r.corrected,
                "reason": r.reason,
            })
            result_text = result_text.replace(r.original, r.corrected)

    return result_text, fixes
```

**验收标准**：
- [ ] 简单算术验证正确率 100%（已有）
- [ ] 方程变形验证：`2x+5=13 → 2x=8` 判定为正确
- [ ] 方程变形验证：`2x+5=13 → 2x=7` 判定为错误并给出正确值
- [ ] 复杂表达式验证：`(3+4)*2 = 14` 正确，`=15` 错误
- [ ] 验证失败时不崩溃，返回原始文本

**预估改动量**：修改 calc_verifier.py（+~150 行）

**当前现状**：`crisis.py` 中用关键词列表匹配，分为 severe/moderate/support 三级，但：

```python
"""增强版危机检测器。

改进点：
1. 轻度情绪词列表 — 不触发危机，但记录情绪状态
2. 上下文排除 — 游戏/影视语境中的"不想活了"不触发
3. 连续负面情绪累积 — 单轮"绝望"不触发，连续2轮才触发 moderate
4. 隐晦表达识别 — "活着没意思""没有意义"等
5. 危机干预后跟进记录
"""

from typing import Optional, List, Dict
import re


# 严重危机关键词（必须触发）
SEVERE_KEYWORDS = [
    "自杀", "想死", "不想活", "活不下去", "结束生命", "一了百了",
    "割腕", "跳楼", "吃药", "安眠药",

]

MODERATE_KEYWORDS = [
    "绝望", "崩溃", "撑不住", "扛不住", "受不了了",
    "没有希望", "看不到希望", "人生没有意义",
    "没人理解我", "没有人关心我", "孤独",
]

# 支持关怀关键词（触发 support 流程）
SUPPORT_KEYWORDS = [
    "被欺负", "霸凌", "校园暴力", "打架",
    "爸妈吵架", "父母离婚", "家暴",
    "考试考砸", "成绩不好", "被老师骂",
    "朋友不理我", "被孤立",
]

# 轻度情绪词（不触发危机，但记录）
MILD_NEGATIVE_KEYWORDS = [
    "好累", "好烦", "好困", "不想上学", "不想写作业",
    "有点难过", "不开心", "郁闷", "无聊",
    "压力大", "有点焦虑", "紧张",
]

# 上下文排除模式（这些语境下的严重词不触发）
CONTEXT_EXCLUSIONS = [
    r'(游戏|电影|电视|小说|动漫|剧情|角色|里面).{0,10}(不想活|想死|自杀)',
    r'(笑|哈哈|开玩笑|逗你|梗).{0,10}(不想活|想死|自杀)',
]


def detect_crisis(text: str, context: dict = None) -> Optional[str]:
    """检测危机等级。

    Args:
        text: 用户输入文本
        context: 上下文信息，包含：
            - consecutive_negative_turns: 连续负面轮数
            - previous_mood: 上一轮心情
            - is_game_context: 是否在讨论游戏/影视

    Returns:
        "severe" / "moderate" / "support" / None
    """
    if not text or not text.strip():
        return None

    context = context or {}
    consecutive_negative = context.get("consecutive_negative_turns", 0)
    is_game_context = context.get("is_game_context", False)

    # 0. 上下文排除
    if is_game_context:
        for pattern in CONTEXT_EXCLUSIONS:
            if re.search(pattern, text):
                return None  # 游戏/影视语境，不触发

    # 1. 严重危机（立即触发）
    for kw in SEVERE_KEYWORDS:
        if kw in text:
            return "severe"

    # 2. 中度危机（需要连续负面情绪累积）
    for kw in MODERATE_KEYWORDS:
        if kw in text:
            if consecutive_negative >= 2:
                return "moderate"
            else:
                return None  # 单轮不触发，但会被记录为负面情绪

    # 3. 支持关怀
    for kw in SUPPORT_KEYWORDS:
        if kw in text:
            return "support"

    return None


def is_mild_negative(text: str) -> bool:
    """判断是否为轻度负面情绪（不触发危机，但记录）。"""
    for kw in MILD_NEGATIVE_KEYWORDS:
        if kw in text:
            return True
    return False


def update_negative_streak(student, text: str, is_crisis: bool) -> int:
    """更新连续负面情绪轮数。

    Returns:
        更新后的连续负面轮数
    """
    if is_crisis:
        # 危机后重置（因为已经处理了）
        student.current_session.consecutive_negative_turns = 0
        return 0

    if is_mild_negative(text):
        student.current_session.consecutive_negative_turns += 1
    else:
        # 非负面情绪，重置计数
        student.current_session.consecutive_negative_turns = 0

    return student.current_session.consecutive_negative_turns
```

```python
from typing import Dict, Optional
from datetime import datetime


class MasteryRecord(BaseModel):
    """单个知识点的掌握度记录（多维）。"""
    concept: float = 0.0          # 概念理解维度
    calculation: float = 0.0       # 计算熟练度维度
    application: float = 0.0       # 应用迁移维度
    confidence: float = 0.0        # 置信度（基于多少道题）
    last_updated: str = ""         # 最后更新时间 ISO 格式
    correct_count: int = 0         # 累计正确数
    total_count: int = 0           # 累计做题数
    error_patterns: Dict[str, int] = Field(default_factory=dict)  # 错误模式统计

    def overall(self) -> float:
        """综合掌握度（加权平均）。"""
        return round(0.4 * self.concept + 0.3 * self.calculation + 0.3 * self.application, 4)

    @property
    def is_mastered(self) -> bool:
        """是否算掌握（综合>=0.7 且 置信度>=0.5）。"""
        return self.overall >= 0.7 and self.confidence >= 0.5

        if self.confidence < 0.3:
            return "uncertain"
        if self.overall >= 0.75:
            return "too_easy"
        if self.overall < 0.25:
            return "too_hard"
        return "ready"
```

```python
"""增强版认知评估：持续更新机制。

改进点：
1. 日常对话中隐式评估（不需要专门做题）
2. 评估结果有衰减（时间越久置信度越低）
3. 新证据自动更新认知画像
4. 评估置信度随证据增加而增加
"""

from datetime import datetime, timedelta
from typing import Optional


# 认知画像衰减参数
COGNITIVE_DECAY_DAYS = 30  # 30天后置信度开始衰减
COGNITIVE_DECAY_RATE = 0.02  # 每周衰减率


def update_cognitive_from_interaction(student, interaction_data: dict):
    """从日常交互中隐式更新认知画像。

    interaction_data 包含：
    - abstract_thinking_evidence: 抽象思维证据（0-1）
    - metacognition_evidence: 元认知证据（0-1）
    - working_memory_evidence: 工作记忆证据
    - math_anxiety_evidence: 数学焦虑证据
    - source: 证据来源（"diagnostic" / "daily" / "error_analysis"）
    """
    profile = student.cognitive_profile

    # 贝叶斯式更新：新证据和旧值加权平均
    weight = 0.3 if interaction_data.get("source") == "daily" else 0.5

    if "abstract_thinking_evidence" in interaction_data:
        profile.abstract_thinking = _weighted_update(
            profile.abstract_thinking,
            interaction_data["abstract_thinking_evidence"],
            weight
        )

    if "metacognition_evidence" in interaction_data:
        profile.metacognition_level = _weighted_update(
            profile.metacognition_level,
            interaction_data["metacognition_evidence"],
            weight
        )

    if "math_anxiety_evidence" in interaction_data:
        profile.math_anxiety = _weighted_update(
            profile.math_anxiety,
            interaction_data["math_anxiety_evidence"],
            weight
        )

    # 更新置信度
    profile.assessment_confidence = min(0.95, profile.assessment_confidence + 0.05)
    profile.last_assessed = datetime.now().isoformat()


def _weighted_update(old: float, new: float, weight: float) -> float:
    """加权更新。"""
    return round(old * (1 - weight) + new * weight, 4)


def apply_cognitive_decay(student):
    """应用认知画像衰减（时间越久置信度越低）。"""
    profile = student.cognitive_profile
    if not profile.last_assessed:
        return

    last_date = datetime.fromisoformat(profile.last_assessed)
    days_since = (datetime.now() - last_date).days

    if days_since > COGNITIVE_DECAY_DAYS:
        weeks = (days_since - COGNITIVE_DECAY_DAYS) / 7
        decay = (1 - COGNITIVE_DECAY_RATE) ** weeks
        profile.assessment_confidence = round(profile.assessment_confidence * decay, 4)


def should_reassess(student) -> bool:
    """判断是否需要重新做认知评估。"""
    profile = student.cognitive_profile
    if profile.assessment_confidence < 0.3:
        return True
    if not profile.last_assessed:
        return True
    days = (datetime.now() - datetime.fromisoformat(profile.last_assessed)).days
    return days > 90  # 超过90天建议重新评估
```

```python
def select_strategy(student, problem_type: str = "", context: dict = None) -> Optional[TeachingStrategy]:
    """根据学生状态和题目类型选择教学策略。

    Returns:
        匹配的策略，或 None（用默认策略）
    """
    context = context or {}
    candidates = []

    for sid, strategy in STRATEGIES.items():
        score = _match_strategy(student, strategy, problem_type, context)
        if score > 0:
            candidates.append((score, strategy))

    if not candidates:
        return None

    # 按匹配分排序，取最高分
    candidates.sort(key=lambda x: x[0], reverse=True)
    return candidates[0][1]


def _match_strategy(student, strategy: TeachingStrategy, problem_type: str, context: dict) -> float:
    """计算策略匹配度（0-1）。"""
    score = 0.0

    # 认知阶段匹配
    if student.cognitive_profile.cognitive_stage in strategy.适用_cognitive_stages:
        score += 0.3
    elif "all" in strategy.适用_cognitive_stages:
        score += 0.2

    # 题型匹配
    if problem_type in strategy.适用_problem_types or "all" in strategy.适用_problem_types:
        score += 0.3

    # 触发条件匹配（简化版，实际可用规则引擎）
    consecutive_wrong = context.get("consecutive_wrong", 0)
    consecutive_correct = context.get("consecutive_correct", 0)
    mastery = context.get("mastery", 0.5)
    abstract_thinking = student.cognitive_profile.abstract_thinking

    if strategy.id == "scaffold_questioning" and mastery < 0.5:
        score += 0.4
    if strategy.id == "analogy_explanation" and consecutive_wrong >= 2 and abstract_thinking < 0.4:
        score += 0.4
    if strategy.id == "error_root_cause" and consecutive_wrong >= 1:
        score += 0.4
    if strategy.id == "positive_reframing" and (consecutive_wrong >= 2 or student.cognitive_profile.math_anxiety > 0.6):
        score += 0.4
    if strategy.id == "variant_practice" and consecutive_correct >= 2 and mastery >= 0.7:
        score += 0.4
    if strategy.id == "decomposition" and context.get("step_count", 1) > 3:
        score += 0.4

    return min(score, 1.0)
```

```python
def select_thinking_model(problem_text: str, problem_type: str = "", student=None) -> Optional[str]:
    """根据题目特征和学生状态选择思维模型。

    Returns:
        思维模型 ID，或 None（不需要特定模型）
    """
    scores = {}

    for mid, trigger in THINKING_MODEL_TRIGGERS.items():
        score = 0.0

        # 关键词匹配
        for kw in trigger["keywords"]:
            if kw in problem_text:
                score += 0.3

        # 题型匹配
        if problem_type in trigger["problem_types"]:
            score += 0.4

        # 学生认知匹配（如抽象思维低的学生优先用类比/图形化）
        if student:
            if mid in ("analogy", "visualization") and student.cognitive_profile.abstract_thinking < 0.4:
                score += 0.3

        if score > 0:
            scores[mid] = score

    if not scores:
        return None

    return max(scores, key=scores.get)
```

**验收标准**：
- [ ] 10 个思维模型都有触发规则（关键词+题型+学生特征）
- [ ] 几何题自动推荐 visualization
- [ ] "至少/最多"题自动推荐 reverse
- [ ] 抽象思维低的学生优先推荐 analogy/visualization
- [ ] select_thinking_model 返回确定性结果

```python
def get_math_context_for_interest(interest: str, topic: str = "") -> Optional[str]:
    """根据兴趣和知识点获取数学情境。

    Returns:
        情境描述，或 None（该兴趣不适合这个知识点）
    """
    if interest not in INTEREST_MATH_CONTEXTS:
        return None

    info = INTEREST_MATH_CONTEXTS[interest]
    if topic and topic not in info["topics"]:
        return None  # 该兴趣不适合这个知识点，不要强行关联

    # 返回第一个匹配的情境（实际可随机选择增加多样性）
    return info["contexts"][0] if info["contexts"] else None


def should_use_interest_context(student, topic: str) -> Optional[str]:
    """判断是否应该用兴趣情境引入知识点。

    规则：
    - 学生有记录的兴趣
    - 该兴趣与当前知识点匹配
    - 学生当前情绪不挫败（挫败时用兴趣可能分散注意力）
    - 不是第一次用这个兴趣（避免过度使用）

    Returns:
        兴趣名称，或 None（不使用兴趣情境）
    """
    if not student.interests:
        return None

    # 检查情绪状态
    if student.current_session.consecutive_wrong >= 2:
        return None  # 挫败时先解决情绪，不用兴趣

    for interest in student.interests:
        context = get_math_context_for_interest(interest, topic)
        if context:
            return interest

    return None
```

- [ ] 学生挫败时不使用兴趣情境（先解决情绪）

```python
根据学生的：

- 知识图谱掌握度
- 漏洞列表
- 认知阶段
- 学习目标（家长/学生设定）

生成本周/本月的学习计划。
"""

from typing import List, Dict, Optional
from datetime import datetime, timedelta
from backend.knowledge.syllabus import all_nodes, get_node
from backend.services.mastery_tracker import MasteryTracker


class LearningPlanItem(BaseModel):
    topic_id: str
    topic_name: str
    chapter: str
    priority: str          # "high" / "medium" / "low"
    reason: str            # 为什么学这个
    estimated_sessions: int  # 预计需要几次课
    prerequisites: List[str] = []


class LearningPlan(BaseModel):
    period: str            # "weekly" / "monthly"
    start_date: str
    end_date: str
    items: List[LearningPlanItem]
    total_estimated_sessions: int


def generate_weekly_plan(student) -> LearningPlan:
    """生成周学习计划。"""
    items = []

    # 1. 高优先级：修复 open 的漏洞
    for gap in student.open_gaps():
        node = get_node(gap.topic_id)
        if node:
            items.append(LearningPlanItem(
                topic_id=gap.topic_id,
                topic_name=node.name,
                chapter=node.chapter,
                priority="high",
                reason=f"存在知识漏洞（{gap.category}），需要修复",
                estimated_sessions=2,
                prerequisites=node.prerequisites,
            ))

    # 2. 中优先级：ZPD 内的知识点（掌握度 0.25-0.75）
    for node in all_nodes():
        mastery_rec = student.mastery.get(node.id)
        if mastery_rec:
            zpd = mastery_rec.zpd_status
            if zpd == "ready":
                items.append(LearningPlanItem(
                    topic_id=node.id,
                    topic_name=node.name,
                    chapter=node.chapter,
                    priority="medium",
                    reason=f"在最近发展区内（掌握度 {mastery_rec.overall:.2f}），适合学习",
                    estimated_sessions=1,
                    prerequisites=node.prerequisites,
                ))

    # 3. 低优先级：已掌握知识点的变式提升
    for node in all_nodes():
        mastery_rec = student.mastery.get(node.id)
        if mastery_rec and mastery_rec.zpd_status == "too_easy" and mastery_rec.application < 0.6:
            items.append(LearningPlanItem(
                topic_id=node.id,
                topic_name=node.name,
                chapter=node.chapter,
                priority="low",
                reason="基础已掌握，但应用迁移不足，可做变式提升",
                estimated_sessions=1,
            ))

    # 按优先级排序，限制本周最多 5 个知识点
    priority_order = {"high": 0, "medium": 1, "low": 2}
    items.sort(key=lambda x: priority_order.get(x.priority, 3))
    items = items[:5]

    total = sum(item.estimated_sessions for item in items)
    today = datetime.now().date()

    return LearningPlan(
        period="weekly",
        start_date=today.isoformat(),
        end_date=(today + timedelta(days=7)).isoformat(),
        items=items,
        total_estimated_sessions=total,
    )
```

**验收标准**：
- [ ] 生成的周计划包含优先级排序的知识点
- [ ] 漏洞修复优先级最高
- [ ] ZPD 内的知识点优先级中等
- [ ] 每周最多 5 个知识点（避免过载）
- [ ] 每个知识点有学习理由和预计课时

### E3. 出题质量无验证

**问题描述**：LLM 出的题可能太简单/太难/有歧义/答案错误，没有验证机制。

**详细实现方案**：

```python
"""出题质量验证器。

验证 LLM 出的题：
1. 答案正确性（SymPy 验证）
2. 难度匹配（与学生掌握度匹配）
3. 无歧义（题目表述清晰）
4. 知识点匹配（题目确实考察目标知识点）
"""

from typing import Optional, Tuple
import sympy as sp
import re


class ProblemValidationResult:
    def __init__(self, is_valid: bool, issues: list = None, corrected: str = ""):
        self.is_valid = is_valid
        self.issues = issues or []
        self.corrected = corrected


def validate_problem(problem: str, answer: str, target_topic: str = "", student_mastery: float = 0.5) -> ProblemValidationResult:
    """验证题目质量。"""
    issues = []

    # 1. 答案正确性验证
    answer_valid = _validate_answer(problem, answer)
    if not answer_valid:
        issues.append("答案可能错误，需要人工复核")

    # 2. 难度匹配（简化：题目数字大小和步骤数估算难度）
    difficulty = _estimate_difficulty(problem)
    if abs(difficulty - student_mastery) > 0.4:
        if difficulty > student_mastery:
            issues.append(f"题目难度（{difficulty:.2f}）高于学生水平（{student_mastery:.2f}），可能太难")
        else:
            issues.append(f"题目难度（{difficulty:.2f}）低于学生水平（{student_mastery:.2f}），可能太简单")

    # 3. 歧义检查（常见歧义模式）
    ambiguity_issues = _check_ambiguity(problem)
    issues.extend(ambiguity_issues)

    return ProblemValidationResult(
        is_valid=len(issues) == 0,
        issues=issues,
    )


def _validate_answer(problem: str, answer: str) -> bool:
    """验证答案是否合理（简化版）。"""
    # 提取答案中的数字
    answer_nums = re.findall(r'-?\d+\.?\d*', answer)
    if not answer_nums:
        return True  # 非数字答案，跳过验证

    # 简单检查：答案应该是有限数
    try:
        for num in answer_nums:
            val = float(num)
            if abs(val) > 1e10:  # 异常大的数
                return False
    except ValueError:
        pass

    return True


def _estimate_difficulty(problem: str) -> float:
    """估算题目难度（0-1）。"""
    difficulty = 0.3  # 基础难度

    # 数字位数越多越难
    large_nums = re.findall(r'\d{3,}', problem)
    difficulty += len(large_nums) * 0.05

    # 运算步骤（逗号/分号分隔的子问题）
    steps = problem.count('，') + problem.count(';') + 1
    difficulty += min(steps * 0.05, 0.3)

    # 关键词难度
    hard_keywords = ["至少", "最多", "证明", "求证", "分类讨论", "动点", "存在性"]
    for kw in hard_keywords:
        if kw in problem:
            difficulty += 0.1

    return min(difficulty, 1.0)


def _check_ambiguity(problem: str) -> list:
    """检查题目歧义。"""
    issues = []
    # 指代不明
    if "它" in problem and problem.count("它") > 1:
        issues.append("'它'出现多次，可能指代不明")
    # 单位缺失
    if re.search(r'\d+\s*[+\-*/]', problem) and "单位" not in problem:
        pass  # 简化，实际需要更复杂的检查
    return issues
```

**验收标准**：
- [ ] 题目答案异常大时被标记
- [ ] 题目难度与学生水平差距>0.4时被标记
- [ ] 题目有歧义时被标记
- [ ] 验证不通过的题目不直接使用，要求 LLM 重新出题

```python
2. 动态休息建议（高认知负荷时更早提醒休息）

from datetime import datetime
from typing import Optional


def estimate_cognitive_load(student) -> float:
    """估算当前认知负荷（0-1）。"""
    load = 0.0

    # 1. 连续错误增加认知负荷
    load += min(student.current_session.consecutive_wrong * 0.15, 0.45)

    # 2. 在同一状态停留越久，认知负荷越高
    load += min(student.current_session.turns_in_current_state * 0.05, 0.3)

    # 3. 题目难度（如果有）
    current_topic = student.current_session.current_topic
    if current_topic and current_topic in student.mastery:
        mastery = student.mastery[current_topic].overall
        load += (1 - mastery) * 0.2  # 不熟练的知识点负荷高

    return min(load, 1.0)


def check_break_needed(student) -> Optional[str]:
    """检查是否需要休息（基于认知负荷+时间）。

    Returns:
        休息建议，或 None（不需要休息）
    """
    today_minutes = _today_study_minutes(student)
    cognitive_load = estimate_cognitive_load(student)

    # 高认知负荷：25分钟就提醒
    if cognitive_load > 0.6 and today_minutes >= 25:
        return "这几道题挺有挑战性的，大脑已经工作了25分钟了！我们休息5分钟吧，站起来走走，看看远处，让大脑充充电。"

    # 常规：60分钟强制提醒
    if today_minutes >= 60:
        return "今天已经学了60分钟了，非常棒！今天就到这里吧，明天继续。记得每天坚持比一次学很久更有效哦。"

    return None
```

```python
        suggestions.append(f"下周可以学习 '{next_topic.topic_name}'，当前掌握度适合学习（在最近发展区内）。")

    # 建议3：思维模型
    if student.cognitive_profile.abstract_thinking < 0.4:
        suggestions.append("可以多使用'图形化思维'和'类比思维'来理解抽象概念，画图帮助理解。")

    # 建议4：学习习惯
    if student.streak_chain < 3:
        suggestions.append("尝试每天固定时间学习15分钟，建立学习习惯，连续学习会获得'不断链'徽章哦。")

    return suggestions[:3]  # 最多3条建议
```

**验收标准**：
- [ ] 周报告包含 insights 字段（至少1条洞察）
- [ ] 周报告包含 suggestions 字段（1-3条可操作建议）
- [ ] 洞察类型包括：进步、漏洞、错误模式、时长变化
- [ ] 建议是具体可操作的，不是"继续努力"这种空话

### H1. 无教学效果闭环验证

**问题描述**：说"掌握了"但一周后不会，没有验证机制。

**详细实现方案**：

#### 新建 `backend/services/mastery_verification.py`

```python
"""掌握度验证机制。

知识点标记为"掌握"后，7天后自动出一道"检索练习题"验证。
- 做对 → 掌握度确认（甚至提升）
- 做错 → 掌握度回退，重新进入教学流程
"""

from datetime import datetime, timedelta
from typing import List, Optional


def get_due_verifications(student) -> List[dict]:
    """获取到期需要验证的知识点。"""
    due = []
    today = datetime.now().date()

    for topic_id, rec in student.mastery.items():
        if rec.is_mastered and rec.last_updated:
            last_date = datetime.fromisoformat(rec.last_updated).date()
            days_since = (today - last_date).days
            if days_since >= 7:  # 掌握7天后验证
                due.append({
                    "topic_id": topic_id,
                    "topic_name": topic_id,  # 实际从知识图谱查
                    "days_since_mastered": days_since,
                    "current_mastery": rec.overall,
                })

    return due


def record_verification_result(student, topic_id: str, is_correct: bool):
    """记录验证结果，更新掌握度。"""
    if topic_id not in student.mastery:
        return

    rec = student.mastery[topic_id]

    if is_correct:
        # 验证通过：掌握度确认，甚至小幅提升
        rec.confidence = min(0.95, rec.confidence + 0.1)
        rec.last_updated = datetime.now().isoformat()
    else:
        # 验证失败：掌握度回退，标记为需要重新学习
        rec.overall = max(0.3, rec.overall - 0.2)  # 简化，实际用多维回退
        rec.confidence = max(0.2, rec.confidence - 0.15)
        rec.last_updated = datetime.now().isoformat()
        # 添加漏洞
        from backend.models.student import Gap
        student.gaps.append(Gap(
            topic_id=topic_id,
            type="concept",
            category="concept_forgetting",
            root_cause="掌握后遗忘，需要间隔复习",
            repair_strategy="重新学习该知识点，增加复习频率",
            status="open",
        ))
```

**验收标准**：
- [ ] 掌握7天后的知识点出现在验证队列中
- [ ] 验证通过 → 置信度提升
- [ ] 验证失败 → 掌握度回退 + 添加漏洞
- [ ] 验证题是"主动回忆"型（不是重新看讲解）

**预估改动量**：新建 mastery_verification.py（~60 行）+ 在会话开始时检查验证队列

```python
"""A/B 测试框架。

支持：
- 按学生随机分组（A组/B组）
- 不同组使用不同的教学策略/prompt
- 记录每组的学习效果指标
- 统计显著性检验
"""

import hashlib
from typing import Optional, Dict
from pydantic import BaseModel


class ABTest(BaseModel):
    id: str
    name: str
    description: str
    variant_a: dict       # A组配置
    variant_b: dict       # B组配置
    metrics: list         # 评估指标列表
    start_date: str
    end_date: str = ""
    active: bool = True


def get_variant(student_id: str, test_id: str) -> str:
    """根据学生ID和测试ID确定分组（确定性，同一学生始终在同一组）。"""
    key = f"{student_id}_{test_id}"
    hash_val = int(hashlib.md5(key.encode()).hexdigest(), 16)
    return "A" if hash_val % 2 == 0 else "B"


def get_config(student, test: ABTest) -> dict:
    """获取学生对应的测试配置。"""
    variant = get_variant(student.id, test.id)
    return test.variant_a if variant == "A" else test.variant_b
```

**验收标准**：

### H3. 对话历史 token 管理

**问题描述**：长对话可能超出 token 限制。

**详细实现方案**：

#### 在 `backend/agent/chat.py` 中添加历史管理

```python
def trim_history(history: list, max_turns: int = 20, max_tokens: int = 6000) -> list:
    """裁剪对话历史，避免超出 token 限制。

    策略：
    1. 保留最近 N 轮对话
    2. 如果仍超 token，保留系统提示和最近几轮
    3. 更早的对话用摘要代替
    """
    if len(history) <= max_turns:
        return history

    # 保留系统提示（第一条）+ 最近 max_turns 轮
    system_msg = history[0] if history else None
    recent = history[-(max_turns * 2):]  # user+assistant 成对

    if system_msg:
        return [system_msg] + recent
    return recent
```

**验收标准**：
- [ ] 对话超过20轮时自动裁剪
- [ ] 裁剪后保留系统提示和最近对话
- [ ] 不丢失关键上下文（学生画像、当前知识点）
